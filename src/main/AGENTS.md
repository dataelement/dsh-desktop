# Electron Main 约束

继承根目录规则；本文件只补充主进程职责。

## 模块边界

- `index.ts` 负责应用生命周期和组装；新的业务规则放入对应模块，避免继续堆叠 IPC handler、HTML 或文件操作实现。
- `runtime/` 管 Harness 子进程；`state/` 管 Profile 和恢复；`update/` 管更新状态；`mobile/` 管配对和桥接；`enterprise/` 管企业登录、凭据和模型网关。模块不得反向导入 `index.ts`。
- 可测试的决策与 Electron/文件系统副作用分离；共享协议放 `src/shared/`，不要让 preload 导入 main 实现。

## IPC 与安全

- 保持 `contextIsolation: true`、`nodeIntegration: false`、sandbox 和 web security；不得为兼容插件放宽 renderer 权限。
- 新增特权 IPC 同时校验发送窗口、主 frame 和参数，沿用现有可信来源校验；不能仅凭 renderer 传来的 ID、路径或布尔值授权。
- 路径/URL/命令参数按操作白名单校验。启动程序优先使用可执行文件与参数数组，不拼接包含外部输入的 shell 命令。
- 导航、权限和外链操作走已有安全模块；不得开放任意 IPC 通道、任意文件读取或命令执行接口。
- Harness 保持随机 loopback 端口；外部访问经手机桥接的配对、会话和来源检查，不能通过绑定公网地址替代。

## 生命周期与持久化

- 子进程启动、停止、重试需要超时、退出处理和资源清理；重复调用不能产生并存 runtime 或遗留监听器。
- 窗口关闭、隐藏到托盘、应用退出和 Harness 重启是不同操作；修改时保留现有平台语义，明确子进程和后台任务是否继续运行。涉及唤醒、网络恢复或多实例唤起时，验证重复事件不会重复启动任务。
- 长时间安装、网络请求和大型目录遍历不能阻塞主进程事件循环；需要进度、超时或取消时沿用对应服务的状态接口，不在窗口事件回调内实现完整任务。
- 配置/迁移写入需考虑原子替换、崩溃恢复和重复执行。失败保留恢复材料，不能只输出成功日志或吞掉错误继续启动。
- 清理目录须验证所有权与实际路径，处理 symlink/junction；平台路径使用 `node:path`，已有路径需要比较物理身份时使用 `realpath`。
- Safe Mode 保持独立 Profile。应用更新不能覆盖用户会话、设置或普通 Profile 数据；插件 generation 的发布规则见 `packages/AGENTS.md`。

## 验证重点

按变更选择正常、失败、重试、取消/退出、重复调用及权限拒绝场景。迁移测试使用临时目录并模拟中途失败；窗口/IPC 用真实应用补充验证；平台相关逻辑在对应平台确认。
