# 新壳约束

继承 `src/main/AGENTS.md`。这里是按官方 Desktop 移植的 Electron 主进程，也是正式包入口。`npm run build` 打进 `out/main/index.js`，应用身份是 `io.dsh.desktop` / `DSH Desktop`。正式包的用户数据目录固定为 `dsh-desktop`；未打包启动和带 `dshDesktopChannel=development` 的开发包使用 `dsh-desktop-dev`。

- 不导入官方强制更新。产品更新使用 `update/update-manager`：安装包里才会自动检查，下载要等用户同意，可以跳过一个版本，也可以从更新卡片安装历史版本。正式包在单实例锁成功且语言校准结束后、注册更新处理程序之前调用 `initializeDesktopUpdateService`，只创建更新策略服务，不附带故障诊断。开发通道不调用它。致命失败交给 `recovery/fatal-entry`，不导入官方恢复对话框。
- `DSH_HOME` 由组装处传入，取 `userData/harness`。正式包的 `userData` 是 `dsh-desktop`，所以现有会话在 `dsh-desktop/harness`。不调用会落到 `~/.dsh` 的默认解析。
- 对版本敏感的上游类型和调用集中到 `upstream-api.ts`。该文件还没有；新增这类调用时先建它，不要散落到各个模块。
- 窗口保持 `contextIsolation`、sandbox、`webSecurity`，`nodeIntegration` 关闭。
- Host 尚未给出认证 Cookie 时，应用请求返回 503，不转发。Host 离开就绪后清掉这一次的启动注入和 Cookie；页面再取启动数据时不会拿到上一次的注入，失败的那次刷新也不会把已经离开的注入交回去。
- 启动 Host 前的顺序是：复制 `profiles/web`，写 `desktop-product.patch.yml`，然后二选一。这份补丁关闭产品分析、`ui-settings-account` 和 `ui-brand-official`，把 `deepseek-account` 的 `desktopPlatform` 留空，并挂上 `dsh-desktop-client-ui`。普通 profile 再挂 `dsh-desktop-workbenches`，根目录是 `dshHomePath('desktop-workbenches')`，并挂 `dsh-desktop-market-installer`、`dsh-desktop-office` 和 `dsh-ppt-composer`。安装器读取 `DSH_DESKTOP_PROFILE`，新壳是 `desktop`，旧壳不设置所以仍是 `web`。Office 资源目录是 primary runtime 的上一级，CLI 在打包资源旁；开发时 `.build/office-runtime` 仍使用 `build/office-cli.mjs`。PPT 工程目录仍是 `dshHomePath('kimi-ppt')`。Safe Mode 不挂 Office 和 PPT。`DSH_DESKTOP_SAFE_MODE=1` 时写不含工作台、市场、Office 和 PPT 的补丁，准备 `desktop-safe-mode`，不跑 generation 投影。否则对 `desktop` 跑投影后再启动。当前 profile 的 `desktop-storage.json` 在页面脚本之前交给 `localStorage`，官方界面据此打开已记住的会话，而不是在已有工作区新建空会话。用量页和充值页不接收账号会话。
- 壳可以导入 `profile/` 的复制、投影、插件维护和 desktop storage，`recovery/` 的致命入口、安全模式 profile、插件列表和维修会话，`desktop-service/` 的登录项诊断，`desktop-protocol`，`mobile/` 的配对桥，`security` 的窗口约束，`update/update-manager`，`repair-agent`、`repair-drafts`、`repair-navigation`，`shell/backend/electron-node-executable`，`sidebar-browser` 的客人策略，以及 `@deepseek-ai/dsh-client-shortcuts` 的协议。快捷键偏好写在 `userData/keybindings.json`。不导入官方强制更新。
- 普通启动在复制 `profiles/web` 之前询问是否导入网页版家目录。只在桌面家目录还没有用户数据时询问。跳过会写下决定；关闭窗口不写决定，也不改网页版目录。Safe Mode 不询问。
- 启动页使用现有的 `build/splash.html` 鲸鱼页，Host 就绪后再进入应用页。不使用官方欢迎窗。网页版导入询问会暂时盖住启动页，决定之后回到鲸鱼页。
- macOS 应用菜单跟随桌面端已选语言，不跟随系统语言。页面切换语言后重画菜单。前三项依次是「关于 DSH Desktop」、「检查更新…」和「了解企业版」。企业页地址是 `https://dshdesktop.com/zh/enterprise/`。应用页上关于使用现有对话框；启动页等其它页面使用系统对话框。设置页底部的企业入口由 `dsh-desktop-client-ui` 提供。普通启动时，企业入口下面有「重启」，它先打开鲸鱼等待页，再重新启动当前 Host，就绪后回到原来的应用页；再下面是「以安全模式重启…」，它带上 `--safe-mode` 重新启动，进入已有的 `desktop-safe-mode`。再下面是「显示 Harness 日志」，它在应用日志目录里定位 `harness.log`。已经在 Safe Mode 时不显示安全模式项，日志项仍留在「重启」后面。关于和检查更新弹窗使用同一份桌面语言，同时只显示一个，右上角可以关闭。已经在 Safe Mode 时不显示这一项。启动失败对话框也提供同一次重启。Safe Mode 启动后，现有 `safe-mode.html` 盖在应用页上，管理普通 `desktop` profile 的第三方插件：可以停用或重新启用，再用一次不带 `--safe-mode` 的重启退出。普通 profile 启动失败且错误点名已安装的第三方插件时，现有 `plugin-recovery.html` 使用原来的恢复页模型：没有升级候选时这一轮停用，主按钮是「一键修复」。Safe Mode 的启动失败仍用原来的短对话框。修复代理已接到当前 Host：侧边栏可以打开维修会话，Safe Mode 页的修复入口也会打开，草稿放进输入框，不会自动发送。Safe Mode 页可以按市场检查结果把插件升级到 `desktop` profile 的 generation，也可以打开、恢复或删除卸载备份。macOS 窗口使用 `hiddenInset`，红绿灯画在侧边栏那一行，收起按钮与关闭按钮同一行。快捷键已接到当前窗口：页面标记 `data-platform`，不标记网页快捷键；文件菜单跟在应用菜单后面，提供“关闭页面或窗口”。侧边栏浏览器使用现有客人策略：每个工作区一个隔离分区，不能打开 Harness 端口，也不能下载或要权限。匹配的快捷键会送到已打开的浏览器页。文件拖放已接到当前窗口：页面只能拖出 Host 授权过的会话文件，或壳临时写下的字节副本。渲染进程不能直接给一个本机路径。应用页挂上现有的更新卡片：同意后才下载，可以跳过一个版本，也可以选择历史版本。手机连接不在这个菜单里。普通启动在 Host 就绪后启动现有配对桥，侧边栏宽时由 `dsh-desktop-client-ui` 打开连接页。桥使用壳已经换到的 Host cookie，配对页展示 web frontend 里的品牌图，Harness 留在回环。添加工作区时使用 Electron 原生文件夹面板。macOS 在启动 Host 前按有效语言目标与实际 locale 比较（显式偏好直接解析，缺省或 `auto` 按系统语言列表解析，与添加工作区确认共用规则），必要时用 `-AppleLanguages` 尝试完整重启一次，不写系统全局语言；失败必须降级继续启动。日常界面支持 Harness 内置八语言，恢复与独立页面在展示边界回退中英文，不改写真实偏好。运行中切换语言后，添加工作区可提示完整重启；选择“稍后重启”则继续打开原生面板，标题沿用本次原生语言，同一目标在当前进程内不重复提示。原生控件语言及安装包重启链路仍须平台实机验收。不用 `osascript`。Safe Mode 不暴露这个入口，也不监听配对端口。自动检查只在已安装的 macOS 或 Windows 包里进行。
- 启动配置对话框、Windows 关闭后留在后台、进程恢复和主窗口渲染重试由 `stability-session.ts` 接到当前窗口。Host 失败时先给出可修复的启动配置；Windows 关闭窗口只隐藏进程，托盘可以重新显示或退出；渲染进程丢失时有限重试，内存耗尽和用尽的图形降级走原生恢复对话框。上一份图形模式写在 `userData/gpu-fallback.json`，并在 Chromium 启动前生效。
- 致命失败先写入 `DSH_HOME/fatal-report.json`，再在应用日志目录写一份 `crash-*.log`。这份记录不向外发送。写完后按 64 KiB 和 500 毫秒上限，把 `userData/plugin-operations` 里的最近操作附进同一份文件。短对话框会写出这份日志的路径。恢复页本身不改。普通 profile 的错误如果点名已安装的第三方插件，就打开现有 `plugin-recovery.html`，文案和修复方案用 `buildPluginRecoveryViewModel`，不另写摘要，也不把 `userData/plugin-operations` 写进页面。市场里有还没试过的兼容版本时这一轮升级，否则停用。已试过的版本记在 `DSH_HOME/repair-journal.json`。主按钮是「一键修复」。其它失败仍显示一条不含认证参数的短对话框。不使用官方 `DesktopFatalRecovery`。这一页不打开修复代理，也不编造升级版本或回退版本。最近插件操作仍只附在崩溃日志里。修复代理从侧边栏或 Safe Mode 页进入当前 Host。
- 第一次启动 Host 前读取 POSIX 登录 shell 环境，和启动页重叠。用账号记录里的 login shell，然后是 `/bin/zsh`、`/bin/bash`、`/bin/sh`。Windows 使用进程已经继承的注册表环境，不运行 PowerShell。读到的 `DSH_*` 和 `ELECTRON_*` 不覆盖桌面进程。失败时用原环境启动，不把变量值写进日志。
- Host 用 `ELECTRON_RUN_AS_NODE` 启动。macOS 上这个进程用应用的 Helper 可执行文件，市场安装再次执行 `process.execPath` 时不会弹出终端。没有实测隐私权限归属之前，不把 Host 改成 UtilityProcess。
- 安装包里的 primary runtime 用 `Resources/office-runtime/primary-runtime`。这是当前 electron-builder 资源布局。
