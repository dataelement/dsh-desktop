# 第 1 编　公文专家团作业流程 SOP v1.3

## 公文写作技能包 · 公文专家团作业流程（轻量 A · 机制优化版 v1.3）

> **形态**：轻量 A——单技能内"角色 / 视角分工"。B 真·专家团（产品化对外）按项目决策**暂缓**，待出效果后再做。
> **本轮优化（机制性 5 项，全部落地）**：①分级触发 ②拟稿后真实性 + 安全先排雷 ③责任链四节点（审核团只评不改）④交付门槛 ⑤客户终检清单抓手。+ ⑥反馈回流闭环。
> **内容资产**：范文样本、保密规则、术语表、提纲扩充等缺失项**本轮不建**，由使用方收集后注入（见《公文内容资产收集清单》）。所有实际数据一律 `【待补充】`，AI 不编造。
> **配套**：生成前准备手册、公文质量检查手册、量化指标体系库、国企专属内容包、病文纠错库、L0—L4 各层。

## 0. 端到端流水线总览

```
分级触发闸门 ─→ 拟稿团(5类主体角色) ─→ 排雷闸门(真实+安全,必须先过)
   │                                        │
   │                                    通过才进
   ▼                                        ▼
全团:六维全审              六维审核团(6专家,只评不改,各出报告)
精简:精简审                          │
                                       ▼
                              主编/合成(按报告改稿,权重表仲裁)
                                       │
                                       ▼
                              客户终检(附通俗清单,责任归客户)
                                       │
                                       ▼
                              反馈回流 → SOP / 素材库迭代
```

**关键变化（相对 v1.2.2 骨架）**：排雷闸门前置且强制；审核团只评不改、改稿独立为主编环节；交付设硬杠；客户终检有通俗清单抓手；全链路有反馈回流。

## 1. 分级触发规则（新增）

> 不是每次都跑全团。按"主体敏感度 × 文种风险"路由，避免无谓耗时也避免简单文种过度审查。

| 路由 | 触发条件（满足任一即全团） | 跑什么 |
|---|---|---|
| **全团** | ①主体 = 党委 / 国企　②文种 = 请示 / 报告（上报）　③涉密敏感　④巡视巡察 / 督察整改类 | 拟稿团全角色 + 排雷闸门 + 六维审核团全审 + 客户终检清单全项 |
| **精简团** | 内部普通通知 / 简单告知 / 常规非上报总结 | 拟稿 + 排雷闸门 + **政治性速查（必做）** + 表达性 + 实效性精简审 + 简化终检清单 |

- **判定驱动**：由 SKILL 第 1 步"六参数"中的单位性质、文种、是否上报自动判定。
- **默认原则**：不确定时 → **默认全团**（宁严勿松）。

> 🔴 **精简团也必须过政治性速查**（v2.0.1 补，解决硬杠悬空）
> **问题**：§6 交付门槛规定"政治性对党委主体必须 ✓"，但精简团的审查范围原先不含政治性。
> 党委主体完全可能走精简团（如党委办公室发一份内部会议通知），此时**该硬杠无人负责**。
>
> **规则**：精简团不跑完整政治性审查，但**必须过速查两项**——
> ① 第 2 册第 2 编 §1.2 固定提法（核心提法一字不改）；② 同编 §4 禁用词（"亲自""老板""隆重召开"及极端评价、网络用语）。
>
> **速查不过 → 升级为全团**，不直接判不合格。

## 2. 拟稿团（5 类主体角色起草）

> 把"第 0—3 步"按单位性质拆成 5 类角色专家。

### 2.1 角色专家分工

| 角色专家 | 负责文稿 | 主调语境 | 必调用（v2.0.1 已映射到册编） |
|---|---|---|---|
| 党委稿专家 | 党委文件、党建述职、民主生活会、巡视巡察整改 | 政治性最高 | 第 3 册第 3 编 §2.1.1（党委） + 第 2 册第 2 编《L0 政治表述规范库》 |
| 政府稿专家 | 政府部门通知/意见/方案/报告/请示 | 实效性最高 | 第 3 册第 3 编 §2.1.2（政府） + 第 4 册第 3 编《量化指标体系库》 |
| 国企稿专家 | 经营分析、职代会、党委报告、改革方案 | 经营+党建双线 | 第 4 册第 4 编《国企专属内容包》 + 第 4 册第 3 编 §3 |
| 事业稿专家 | 总结、汇报、服务方案 | 实效性+表达性 | 第 3 册第 3 编 §2.1.4（事业） |
| 基层稿专家 | 村/社区/集体公文、公示、一事一议 | 真实性+表达性、通俗 | 第 3 册第 3 编 §2.1.6（基层） + 四议两公开 |

### 2.2 作业步骤
```
① 执行 SKILL 第 0 步：读 第 1 册第 1 编《生成前准备手册》四步（政治初检 → 要素矩阵 → 事实索取 → 路由）
　 **+ 确认公开度 L1—L4**（第 1 册第 3 编 §5）——L1 涉密立即停止在本技能处理
② 锁定角色对应的 第 3 册第 3 编 L2/L3 语境 + 第 3 册第 1 编《L1 文种骨架》
③ 调取素材：目标任务类 → 第 4 册第 3 编《量化指标体系库》；国企类 → 第 4 册第 4 编《国企专属内容包》
④ 按骨架生成初稿，事实缺失处标 【待补充：需要什么】
⑤ 拟稿团要素自检：第 3 册第 2 编要素矩阵必需要素齐全否（缺则补或标待补充）
⑥ **输入侧安全自查**（第 1 册第 3 编 §2.4）：扫用户提供的素材有无密级标志、未脱敏身份证号 / 手机号、
　 内部会议纪要原件、未公开数据——发现即提示用户，**不带着进正文**
```

### 2.3 铁律与产出
- 事实素材来自用户（L5），**绝不编造**。
- **产出**：初稿 + 一份"拟稿团要素自检表"（要素齐 / 待补充项清单）。

---

## 3. 排雷闸门（新增 · 拟稿后第一道，强制）

> 把质量检查手册"先排雷"固化到拟稿环节。拟稿是编造风险最高处，必须最先过红线。

- **强制顺序**：拟稿团交稿 → **真实性专家 + 安全专岗先审**（一票否决）→ 通过才进 §4 六维其他视角。
- **不通过处理**：真实性（编造/无来源/张冠李戴）或安全性（涉密/隐私/敏感未脱敏）命中 → 一票否决，退回拟稿团补事实 / 脱敏，**不得进后续视角**。
- **输出**：排雷结论（通过 / 退回 + 原因）。

---

## 4. 六维审核团（只评不改）

> 核心纪律：审核团**只出报告，不改稿**。改稿是 §5 主编环节的事，避免既当裁判又当运动员。

### 4.1 六维审查专家
| 专家 | 审查内容 | 调用（v2.0.1 已映射到册编） |
|---|---|---|
| 政治性 | 提法/机构名/排序/禁用词/港澳台民族宗教 | 第 2 册第 2 编《L0 政治表述规范库》 |
| 合法性 | 权限/前置程序(国企党委前置)/依据文号/抵触上位法 | 第 2 册第 1 编《L0 硬规则层》 + 第 4 册第 4 编《国企专属内容包》§2 |
| 真实性(红线) | 数据可溯源/无编造/人名地名职务准 | 用户提供的 L5 事实素材 + 第 3 册第 2 编事实索取清单 |
| 逻辑性 | 结构/层次/因果/论据 | 第 3 册第 1 编《L1 文种骨架》 + 第 3 册第 2 编《要素矩阵》 |
| 表达性 | 文种/格式18要素/标点数字 | 第 2 册第 1 编第 10 节 + 第 5 册《国标原文补编》 |
| 实效性 | 指标可量化/责任/时限/保障具体 | 第 4 册第 3 编《量化指标体系库》 + 第 4 册第 4 编《国企专属内容包》 |

> **安全性为何不在上表**：安全性是隐性第七维，已在 §3 排雷闸门由安全专岗单独审过（一票否决），
> 不进六维审核团，避免重复。**例外**：若 §5 主编环节往稿中补入了新事实或新表述，交付前须**回头补跑一次**
> 第 1 册第 3 编 §8 排雷检查单——新增内容是新的泄密面。

### 4.2 作业与产出
- 每专家对照 第 1 册第 2 编《公文质量检查手册》本视角条目，命中问题 → 定位 第 4 册第 5 编《病文纠错库》病例类型（B1—B14）；
  安全性问题对照 第 1 册第 3 编病例 **J1—J12**（注意：不是 B 类，两套编号不得混用）。
- **产出**：六维分维度质检报告（每维：通过 / 待改 / 不合格 + 问题定性 + 原句 + 改写建议 + 要点）。**不改稿**。

## 5. 主编 / 合成（独立改稿环节，新增）

> 解决"谁改稿"的含糊。审核团交报告，主编环节据此改，并仲裁跨视角冲突。

- 依据六维报告生成**修改稿**。
- **跨视角冲突仲裁**：以六维权重表为准（党委重政治性、政府/国企重实效性、事业重实效+表达、基层重真实+表达）。
- 主编不直接引入新事实，仅按报告与用户已供素材调整。

---

## 6. 交付门槛（新增）

> 六维"通过/待改/不合格"后，什么算可交给客户，必须有硬杠。

- **硬杠（必须过才交付）**：真实性 ✓ 且 安全性 ✓；政治性对党委主体必须 ✓（精简团按 §1 速查口径判定）。
- **可带项交付**：其余维度可带"待改 / 待补充"交付，但须显式列出"待客户确认项"，不得隐藏。
- **未过硬杠 → 按下列顺序退回，不得跳步**：

| 未过项 | 退回环节 | 动作 |
|---|---|---|
| 真实性不实 / 安全性涉密 | 直接退回 **§2 拟稿团**（不经 §5） | 补事实 / 脱敏后重新拟稿——源头问题，改稿只会掩盖 |
| 政治性不过（党委主体） | 先退回 **§5 主编/合成** | 按政治性专家报告改稿；报告指出需改定性 / 补依据而主编无法自行完成的，再退 **§2 拟稿团** |
| 其余维度"不合格" | 退回 **§5 主编/合成** | 按报告改稿后重走 §4 复审；两次复审仍不合格，退 **§2 拟稿团** 重写 |

> **为什么这样分层**（v2.0.1 补）：原表述"回到 §2 或 §3"**跳过了 §5 主编环节**——六维审核团只评不改，
> 若报告不交给 §5 执行而直接退回拟稿团，等于报告白出，也与 §5"独立改稿环节"的设立自相矛盾。
> 真实性与安全性是**源头问题**，改稿只会掩盖，故直退拟稿团；其余多为**表述问题**，交 §5 依报告改即可。

## 7. 客户终检（附通俗清单抓手，新增）

> 决策：客户自己检查、责任归客户。但客户多半不懂公文，必须给"通俗版终检清单"作抓手，否则风险只是转移而非消除。

### 7.1 交付物
修改稿 + 六维质检报告 + `【待补充】`清单 + `【待核实】`清单 + **通俗版终检清单**。

### 7.2 通俗版终检清单模板（客户逐条打钩）
```
【公文终检清单 · 请您过目后打钩】
1. [ ] 稿子里所有数字，是不是您提供给我的？（没提供的都标了【待补充】）
2. [ ] 引用的文件 / 文号，您核实过是真的、现行有效的吗？
3. [ ] 有没有您从没说过、看起来像 AI 自己加进去的表述或结论？
4. [ ] 政治提法（如"两个维护""中央八项规定"）和您单位惯用的一致吗？
5. [ ] 责任单位、完成时间写清楚了吗？有没有"加强领导"这类空话？
6. [ ] 有没有涉密内容 / 个人隐私 / 未公开敏感数据没脱敏的？
```
- 客户打钩确认即责任闭环。AI 不替代客户对真实性、合规性的最终判断。

---

## 8. 反馈回流闭环（轻量，新增）

- 每次交付后请客户标：哪些被改、哪些返工、哪些看不懂。
- 回流改进：SOP 本身（流程优化）+ 素材库（待内容资产收集注入后）。
- 记录轻量，不增加客户负担（附在终检清单后可选项）。

---

## 9. 红线与责任边界

- **AI 质量底线（自守）**：不编造事实；真实性 / 安全性一票否决（AI 自检层面）。目的：减少客户返工，非替客户担责。
- **责任归属（项目决策）**：最终公文责任归客户；客户终检为责任闭环。
