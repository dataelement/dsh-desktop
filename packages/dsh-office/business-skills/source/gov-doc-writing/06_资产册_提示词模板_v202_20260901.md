# 第 1 编　AI 提示词资产库

## 公文写作技能包 · AI 提示词资产库

> **定位**：把技能包各层能力封装成**可复制、可直接用**的提示词模板。别人拿到提示词就能干活，不必先读懂整套技能包。
> **建立日期**：2026-09-01　**版本**：v1.0
> **适用范围（最高优先级）**：**通用党政机关 + 国有企业通用框架**，不针对任何单一行业单独封装。
> **配套**：SKILL 技能入口、第 1 册第 1 编《生成前准备手册》、公文质量检查手册、第 1 册第 3 编《安全保密检查规则库》、量化指标体系库、第 4 册第 4 编《国企专属内容包》、病文纠错库、公文专家团 SOP v1.3。

### 0. 使用方式：先分清三类提示词

| 类型 | 干什么用 | 什么时候用 |
|---|---|---|
| **P 型（生产型）** | 让 AI 把稿子**写出来** | 起草、改写、扩写、压缩 |
| **Q 型（质检型）** | 让 AI **挑错**，不改稿 | 写完自检、交叉把关 |
| **A 型（Ask 索取型）** | 让 AI **向你提问**要素材 | 动笔前，避免编造 |

> **最常见的用法错误**：把 Q 型当 P 型用——让 AI 边审边改，结果既当裁判又当运动员，改完还不知道改了什么。**质检和改稿分成两次对话**。

**变量约定**：`{{ }}` 内为需替换内容。方括号 `[ ]` 内的部分按需要取舍。

---

### 1. 提示词通用骨架（五段式）

所有 P 型提示词都按这五段组装，**缺一段效果就掉一半**：

```
① 角色与任务：你是谁、要写什么
② 六个参数：单位性质 / 部门 / 行文方向 / 文种 / 角色 / 场合与篇幅
③ 事实素材：我给你的材料（有多少给多少，没有的不许编）
④ 硬约束：不许做什么（编造、政治表述错、空话、泄密）
⑤ 输出格式：要什么结构、要不要附待补充清单
```

> **为什么必须写第④段**：不写约束，AI 就会用"合理想象"填补空白——而公文里最贵的错误恰恰是"看起来很合理的编造"。

### 2. 主控提示词（P0 · 一键跑全流程）

```
你是一位有二十年经验的公文起草专家。请按下列流程为我起草一份公文，严格分步骤执行，每步完成后再进入下一步。

【第一步 · 参数确认】
请先复述并确认以下参数，如有缺失或不确定，向我提问，不要自行假设：
1. 单位性质：{{党委 / 政府 / 政府部门 / 事业单位 / 国有企业 / 村集体 / 园区}}
2. 具体部门：{{ }}
3. 行文方向：{{上行 / 下行 / 平行}}
4. 文种：{{ }}
5. 我的角色：{{代笔（为什么层级代笔）/ 一把手 / 副职 / 部门负责人 / 个人}}
6. 场合与篇幅：{{ }}
7. 公开度：{{涉密 / 内部 / 限制公开 / 主动公开}}

【第二步 · 要素核对】
按该文种的必需要素（依据背景、目标任务、举措内容、责任分工、时序节点、保障机制、检验标准），列出本文种必须具备的要素清单，并标出最容易漏的项。

【第三步 · 素材索取】
根据上述要素，列出你必须向我索取的事实清单（数据、文号、人名地名职务、时间节点等）。一次问清，我回答后你再动笔。

【第四步 · 起草】
我提供素材后，你按该文种骨架起草。硬约束：
· 我未提供的所有事实，一律标【待补充：需要什么】，绝不用看似合理的内容填补
· 政治表述必须规范：固定提法一字不改、机构首次用全称、禁用"亲自""老板""隆重召开"等词、涉港澳台与民族宗教表述不得变通
· 责任单位、完成时限、检验标准必须具体到部门与日期，不写"加强领导""高度重视"这类无信息量的话
· 不得写入涉密内容、未公开数据、未脱敏的个人信息
· 语言平实，不用排比堆砌、不用空洞形容词

【第五步 · 自检】
成稿后按六维（政治性、合法性、真实性、逻辑性、实效性、表达性）+ 安全性逐维自查，安全性须过安全排雷检查单。输出：
1. 成稿
2. 六维自查结果（每维：通过 / 待改 / 不合格 + 问题说明）
3. 【待补充】清单
4. 【请您核实】清单

现在请从第一步开始。
```

> **步号映射（v2.0.1 补）**：本提示词的"第一步—第五步"是**对话内的执行步**，与 SKILL 工作流的
> "第 0—5 步"是两套编号，对照如下，避免混淆：
>
> | 本提示词 | SKILL 工作流 | 内容 |
> |---|---|---|
> | 第一步 参数确认 | 第 1 步（六参数）+ 第 0 步（公开度） | 单位性质、部门、方向、文种、角色、篇幅、**公开度 L1—L4** |
> | 第二步 要素核对 | 第 0 步② | 必需要素 + 最易漏项 |
> | 第三步 素材索取 | 第 2 步 | 事实清单，一次问清 |
> | 第四步 起草 | 第 3 步 | 按骨架生成 |
> | 第五步 自检 | 第 4 步 | 六维 + 安全性 |

### 3. 按文种的生产提示词（P1—P14）

> 用法：复制对应文种的提示词 → 填 `{{ }}` → 附素材 → 发出。
> 每个提示词已内含该文种最易漏项（来自要素矩阵），不必另加说明。

#### P1 · 通知

```
请代我起草一份《{{标题}}》通知。

【参数】发文单位：{{ }}；主送：{{ }}；行文方向：下行；篇幅：{{ }}。
【背景】{{事项由来、依据文件及文号}}
【素材】{{具体事项、要求、时间节点、责任单位}}

【本通知必需要素，缺一不可】
① 依据背景（引用依据文件全称 + 文号）
② 具体事项（做什么，分条列项）
③ 责任单位（具体到部门，不写"各单位"）
④ 完成时限（具体到日期）
⑤ 工作要求（怎么报、报给谁、什么形式）

【硬约束】
不写"加强领导""提高认识"这类无信息量的套话；每条要求都要能被执行和检查；
数据与文号我未提供的一律标【待补充】；政治表述规范；不涉密不含未脱敏个人信息。

【输出】成稿 + 本通知必需要素对照表（逐项说明是否写到位）+ 【待补充】清单。
```

#### P2 · 请示

```
请代我起草一份《关于{{事项}}的请示》。

【参数】发文单位：{{ }}；主送机关：{{ }}；行文方向：上行。
【素材】{{缘由、必要性、拟办方案、涉及的数据与政策依据}}

【本请示必需要素，缺一不可】
① 请示缘由（为什么必须办：现状 + 问题 + 必要性，要有说服力）
② 拟办意见（怎么办，必须有明确倾向，不能只摆问题）
③ 政策依据（引用上位文件全称 + 文号）
④ 一文一事（只请示一件事）
⑤ 结语（妥否，请批示。/ 以上请示，如无不妥，请批转……）

【硬约束】
严禁一文多事；严禁只报问题不给方案；拟办意见必须明确（要多少钱、要什么政策、什么时候要）；
数据未提供一律标【待补充】；不得越级请示（如必须越级，须抄送被越过的机关）。

【输出】成稿 + 要素对照表 + 【待补充】清单 + 提示：本文需不需要抄送、需不需要附附件。
```

#### P3 · 报告

```
请代我起草一份《关于{{事项}}的报告》。

【参数】发文单位：{{ }}；主送：{{ }}；行文方向：上行；篇幅：{{ }}。
【素材】{{工作开展情况、数据、做法、成效}}

【本报告必需要素，缺一不可】
① 工作开展情况（做了什么，用数据说话）
② 成效（量化，不要"明显提升"，要"从 X 提高到 Y"）
③ 存在问题（必须写实，只报喜不报忧是报告的典型错误）
④ 下一步打算（针对问题提出，不是重复前文）

【硬约束】
报告中不得夹带请示事项（如需批准，另发请示）；
问题部分要具体，写"某某环节推进滞后，原因是什么"，不写"还存在一定差距"；
数据一律来自我提供的素材，未提供标【待补充】。

【输出】成稿 + 要素对照表 + 【待补充】清单。
```

#### P4 · 工作方案 / 实施方案

```
请代我起草一份《{{ }}工作方案》。

【参数】发文单位：{{ }}；实施范围：{{ }}；完成时限：{{ }}；篇幅：{{ }}。
【素材】{{上位依据、现状与目标、已有基础、可调动资源}}

【本方案必需要素，缺一不可】
① 指导思想（一句话，规范提法）
② 工作目标（总体目标 + 可量化指标，指标须有基期值与目标值）
③ 主要任务（分条，每条对应一个目标）
④ 责任分工（任务 → 牵头单位 → 配合单位，建议出表）
⑤ 时序节点（分阶段：启动 / 推进 / 攻坚 / 总结，每阶段有截止时间）
⑥ 保障措施（组织、资金、人员、督查、考核，各一句具体动作）
⑦ 检验标准（怎么算完成，可考核）

【硬约束】
任务要能对应到部门，不能"全体负责"等于没人负责；
保障措施要写具体动作与责任方，不写"加强组织领导"；
指标我未提供的一律标【待补充】。

【输出】成稿 + 责任分工表（可作为附件）+ 时序节点表 + 【待补充】清单。
```

#### P5 · 领导讲话稿

```
请代我起草一篇{{场合}}讲话稿。

【参数】讲话人职务：{{ }}；讲话人层级：{{一把手 / 副职 / 部门负责人}}；
场合：{{动员会 / 推进会 / 总结表彰会 / 座谈会 / 调研座谈会}}；
听众：{{ }}；篇幅：{{约{{ }}字}}；时长：{{ }}。

【素材】{{会议背景、已掌握的情况、本单位做法与数据、上级要求}}

【结构要求】
① 开场（点明会议目的，不写"隆重召开"）
② 第一部分：统一思想 / 提高认识——讲为什么干
③ 第二部分：明确任务 / 突出重点——讲干什么，分条讲具体
④ 第三部分：强化保障 / 压实责任——讲怎么干，落到部门与人
⑤ 结尾（提要求，简短有力，不喊口号）

【硬约束】
层级决定站位：一把手讲全局与方向，副职讲分工与落实，部门负责人讲具体业务；
讲成绩要克制，讲问题要具体，讲任务要可考核；
不用排比堆砌，不用"重要讲话""亲自""老板"等词；
不使用我未提供的数据与案例，未提供标【待补充】。

【输出】成稿 + 【待补充】清单 + 提示：哪些地方需要讲话人本人确认（如涉及未公开事项、具体人名）。
```

#### P6 · 工作总结

```
请代我起草一份《{{单位}}{{年度/季度}}{{专项}}工作总结》。

【参数】单位性质：{{ }}；周期：{{ }}；篇幅：{{ }}；报送对象：{{上级 / 内部}}。
【素材】{{完成情况、数据、做法、存在问题、下一步计划}}

【本总结必需要素，缺一不可】
① 总体情况（一段话概括，用核心数据）
② 主要做法与成效（分条，每条：做法 + 数据 + 成效）
③ 存在问题（必须写实，且要与下一步措施对应）
④ 下一步工作打算（针对问题，不重复成效）

【硬约束】
做法要写"做了什么具体动作"，不写"高度重视、认真贯彻"；
成效要量化，用对比（同比 / 环比 / 与目标比）；
问题要具体且与措施一一对应，避免"问题归问题、打算归打算"两张皮；
数据未提供一律标【待补充】。

【输出】成稿 + 要素对照表 + 【待补充】清单。
```

#### P7 · 汇报材料

```
请代我起草一份向{{上级单位}}的汇报材料。

【参数】汇报单位：{{ }}；汇报人：{{ }}；场合：{{调研 / 检查 / 会议}}；篇幅：{{ }}。
【素材】{{工作进展、做法、数据、亮点、困难与请求}}

【本汇报必需要素，缺一不可】
① 基本情况（一句话定位 + 关键数据）
② 主要做法（分条，突出本单位特点）
③ 成效与亮点（可量化，最好有对比与案例）
④ 存在困难（实事求是，不要过度诉苦）
⑤ 请示事项 / 请求支持（如需，明确具体）

【硬约束】
突出本单位特色动作，不写放之四海皆准的通用做法；
困难要具体并给出原因，请求要明确（要什么、要多少）；
数据未提供一律标【待补充】。

【输出】成稿 + 【待补充】清单。
```

#### P8 · 通报

```
请代我起草一份《关于{{ }}的通报》。

【参数】发文单位：{{ }}；通报类型：{{表彰 / 批评 / 情况通报}}；主送：{{ }}。
【素材】{{事实经过、处理结果、依据}}

【本通报必需要素，缺一不可】
① 事实经过（时间、地点、当事人、经过，客观准确）
② 性质认定与依据（依据什么规定认定）
③ 处理结果（表彰决定 / 处分决定 / 情况结论）
④ 要求或号召（针对同类单位 / 人员）

【硬约束】
事实必须来自我提供并经核实的材料，严禁推测与渲染；
涉及个人信息的须脱敏（姓名用"某某"、号码打星号）；
批评类通报表彰前须确认是否已走完程序、是否可公开；
未定论的事项不得写成结论。

【输出】成稿 + 【待补充】清单 + 提醒：本稿公开度建议（内部 / 可公开）。
```

#### P9 · 会议纪要

```
请根据我提供的会议记录整理一份《{{ }}会议纪要》。

【参数】会议名称：{{ }}；时间：{{ }}；地点：{{ }}；
主持人：{{ }}；参会人员：{{ }}；纪要类型：{{议定事项纪要 / 讨论情况纪要}}。

【素材】{{会议记录原文}}

【本纪要必需要素，缺一不可】
① 会议基本情况（时间、地点、主持人、参会人员、议题）
② 议定事项（分条，每条明确：事项 + 责任单位 + 完成时限）
③ 待议事项（本次未议定的，写明后续安排）

【硬约束】
只记录议定事项，讨论过程中的分歧与发言者姓名不写入对外版本（如内部需要另出版本）；
议定事项必须落到责任单位和时限，不写"原则同意推进"；
纪要不越权，不得记录超出会议权限的决定；
涉密会议内容不得进入非涉密处理环节。

【输出】成稿 + 议定事项落实表（事项 / 责任单位 / 完成时限）+ 提醒：本纪要建议按内部件管理。
```

#### P10 · 函（商洽函 / 答复函 / 告知函）

```
请代我起草一份《关于{{ }}的函》。

【参数】发文单位：{{ }}；主送单位：{{ }}（不相隶属机关）；
函的类型：{{商洽函 / 询问函 / 答复函 / 告知函 / 请批函}}。

【素材】{{事由、依据、具体事项}}

【本函必需要素】
① 事由与依据（为什么要发这封函）
② 具体事项（商洽什么 / 答复什么）
③ 结语（特此函商，盼予函复。/ 特此函复。/ 特此函告。）

【硬约束】
语气平和对等，是"商量"不是"命令"，不用"望遵照执行"这类下行口吻；
答复函必须先引述来函标题与文号，再作答复；
一文一事，简洁。

【输出】成稿 + 【待补充】清单。
```

#### P11 · 意见（实施意见）

```
请代我起草一份《关于{{ }}的实施意见》。

【参数】发文单位：{{ }}；主送：{{ }}；篇幅：{{ }}。
【素材】{{上位文件依据、本地实际、拟采取的政策措施}}

【本意见必需要素，缺一不可】
① 总体要求（指导思想 + 基本原则）
② 工作目标（分阶段，含量化指标）
③ 政策措施（分条，每条要可操作：谁来做、做什么、怎么做）
④ 组织实施（责任分工 + 时限 + 督查考核）

【硬约束】
措施必须有操作性（可执行、可检查），不写原则性空话；
不得与上位文件抵触，有突破的须注明依据；
指标未提供一律标【待补充】。

【输出】成稿 + 措施操作性自查表（每条措施：是否可执行 / 是否可检查 / 责任是否明确）+ 【待补充】清单。
```

#### P12 · 公示

```
请代我起草一份《{{ }}公示》。

【参数】公示单位：{{ }}；公示事项：{{ }}；公示期：{{ }}天；举报方式：{{电话 / 邮箱 / 地址}}。
【素材】{{公示名单或事项内容}}

【本公示必需要素，缺一不可】
① 公示事项与依据
② 公示内容（名单 / 数据，须脱敏）
③ 公示期限（起止日期，一般不少于 5 个工作日）
④ 受理方式与受理单位（电话、邮箱、地址、受理时间）
⑤ 反映问题的方式要求（提倡实名、须实事求是）

【硬约束】
个人信息必须脱敏：身份证号保留前 6 位 + 后 4 位打星，手机号中间四位打星，
住址只到乡镇 / 街道，未成年人不得公开姓名与学校；

【输出】成稿 + 脱敏提示清单（逐项说明哪些字段需再核对）+ 【待补充】清单。

#### P13 · 述职报告 / 述责述廉

```
请代我起草一份{{姓名 / 职务}}的{{年度}}述职报告。

【参数】单位性质：{{ }}；职务：{{ }}；篇幅：{{ }}。
【素材】{{本年度履职情况、数据、廉洁自律情况、存在不足}}

【本述职必需要素，缺一不可】
① 履职情况（分条：抓了什么、结果如何，用数据）
② 廉洁自律情况（述责述廉须单列）
③ 存在不足（必须真诚具体，不写"学习还不够深入"这类假不足）
④ 下一步改进措施（对应不足）

【硬约束】
第一人称；成绩用数据支撑，不夸大；
不足要具体到某个方面、某个环节，不写放之四海皆准的空话；
改进措施要对应不足，不另起一套。

【输出】成稿 + 【待补充】清单。
```

#### P14 · 对照检查材料

```
请代我起草一份{{ }}对照检查材料。

【参数】单位性质：{{ }}；职务：{{ }}；对照主题：{{ }}。
【素材】{{个人 / 班子实际、已查摆的问题、征求意见情况、上级点出的问题}}

【本材料必需要素，缺一不可】
① 存在的突出问题（分条，每条有具体表现 + 具体事例）
② 产生问题的原因剖析（对应问题，挖到思想根源）
③ 今后的努力方向和改进措施（对应问题，可操作、可检验）

【硬约束】
问题要有事例支撑，不写"有时""一定程度"这类模糊表述；
原因剖析要触及主观，不推给客观条件；
措施要具体、有时限，不写"进一步加强学习"；
严禁套用模板导致与他人雷同。

【输出】成稿 + 【待补充】清单 + 提醒：本材料需本人逐条核实问题事例的真实性。
```

### 4. 按主体的语气提示词（Y1—Y5）

> 用于给已写好的稿子**调整语气与站位**，或叠加在生产提示词末尾。

```
【Y1 党委 / 党建稿】
语气调整为党委口径：强调政治站位、把方向管大局保落实，
党建与业务融合表述（不能把党委写成政府），突出"党建引领 + 责任传导"，
政治性为第一权重，固定提法一字不改。

【Y2 政府 / 政府部门稿】
语气调整为政府口径：强调执行与成效，必有量化指标、责任分工、完成时限，
突出可操作性，实效性为第一权重，少讲道理多讲办法。

【Y3 国企稿】
语气调整为国企口径：经营指标与党建引领双线并行，
重大事项须体现党委前置研究，经营数据用规范口径，
改革类内容体现"提高核心竞争力、增强核心功能"。

【Y4 事业单位稿】
语气调整为事业单位口径：突出公益属性与服务效能，
忌行政命令口吻，对上谦敬、对服务对象平实。

【Y5 基层稿】
语气调整为基层口径：通俗易懂，少用书面长句，
多具体事、具体人、具体数据，篇幅宜短，
重要事项须写明经会议决议（如"四议两公开"）。
```

### 5. 专家团角色提示词（E0—E13）

> 对应 SOP v1.3。**关键纪律：审核类提示词一律"只评不改"。**

#### E0 · 分级触发判定

```
请根据以下参数判定本次应跑"全团"还是"精简团"：
单位性质：{{ }}；文种：{{ }}；是否上报：{{ }}；是否涉敏感：{{ }}。
规则：主体为党委 / 国企，或文种为请示 / 报告（上报），或涉密敏感，或属巡视巡察 / 督察整改类 → 全团；
内部普通通知 / 简单告知 / 常规非上报总结 → 精简团；不确定 → 默认全团。
输出：判定结果 + 理由 + 本次将执行哪些环节。
```

#### E1—E5 · 拟稿团角色提示词

```
【E1 党委稿专家】
你是党委公文起草专家。按党委口径起草{{文种}}。必用：党建与业务融合表述、
政治性优先、固定提法一字不改。产出：初稿 + 要素自检表 + 【待补充】清单。

【E2 政府稿专家】
你是政府公文起草专家。按政府口径起草{{文种}}。必用：量化指标、责任分工表、
完成时限。产出：初稿 + 要素自检表 + 【待补充】清单。

【E3 国企稿专家】
你是国企公文起草专家。按国企口径起草{{文种}}。必用：经营指标 + 党建引领双线、
重大事项体现党委前置研究。产出：初稿 + 要素自检表 + 【待补充】清单。

【E4 事业稿专家】
你是事业单位公文起草专家。按事业口径起草{{文种}}。突出公益属性与服务效能，
忌行政命令口吻。产出：初稿 + 要素自检表 + 【待补充】清单。

【E5 基层稿专家】
你是基层公文起草专家。通俗简短，多具体事例与数据，重要事项写明经会议决议。
产出：初稿 + 要素自检表 + 【待补充】清单。
```

#### E6 · 排雷闸门（真实性 + 安全性，一票否决）

```
你现在是排雷岗，只做红线审查，不做其他评价。
对下面这篇稿子逐条检查：

【真实性】
· 所有数据是否都有来源（用户提供的素材 / 已公开来源）？找出无来源的
· 是否存在张冠李戴（数据配错单位 / 时间 / 事项）
· 人名、地名、职务、文号是否准确
· 是否存在"看似合理但用户从未说过"的表述

【安全性】
· 是否含涉密内容或可反推的转述
· 个人信息是否已脱敏（身份证号、手机号、住址、账号、健康、未成年人）
· 是否存在组合信息可唯一锁定到个人
· 是否含未公开政策、人事酝酿、纪检线索、标底底价
· 是否含内部矛盾、未形成结论的分歧、上级批评原话

【输出】
通过 → 直接写"排雷通过，可进入六维审核"
不通过 → 列出命中项（原文位置 + 原因 + 处置建议），写明"退回拟稿环节"
你只判定，不改稿。
```

#### E7—E12 · 六维审核团（只评不改）

```
【E7 政治性审核专家】
只审查政治性：固定提法是否一字未改、机构名称与简称是否规范、
职务排序是否正确、有无禁用词、涉港澳台与民族宗教表述是否规范。
输出：通过 / 待改 / 不合格 + 问题清单（原句 + 问题 + 建议改法）。只评不改。

【E8 合法性审核专家】
只审查合法性：发文主体权限是否越权、前置程序是否履行（国企须党委前置研究）、
依据文件与文号是否真实有效、是否与上位法抵触、程序是否合规。
输出同上。只评不改。

【E9 真实性审核专家】
只审查真实性：数据可溯源、无编造、人名地名职务准、时间与事项对应。
输出同上。只评不改。

【E10 逻辑性审核专家】
只审查逻辑性：结构层次、因果关系、论据支撑、前后一致、有无自相矛盾与循环论证。
输出同上。只评不改。

【E11 表达性审核专家】
只审查表达性：文种是否得当、格式要素（标题 / 主送 / 正文 / 附件 / 落款 / 成文日期等）是否齐全、
标点与数字用法是否规范、有无空话套话与语病。
输出同上。只评不改。

【E12 实效性审核专家】
只审查实效性：指标是否可量化（有基期值与目标值）、责任是否到部门、时限是否到日期、
保障是否具体、有无可考核的检验标准。
输出同上。只评不改。
```

#### E13 · 主编合成（按报告改稿 + 仲裁）

```
你现在是主编。下面是初稿 + 六维审核报告。请：
① 按审核报告逐条修改初稿（不改事实，只按报告调整表述与结构）
② 跨维度冲突按权重仲裁：党委重政治性、政府与国企重实效性、
   事业单位重实效性 + 表达性、基层重真实性 + 表达性
③ 不引入任何报告与原始素材之外的新事实
④ 输出：修改稿 + 修改对照表（原句 → 改后 → 依据哪条审核意见）+ 仍未解决项
```

#### Q1 · 六维全检（终检用）

```

③ 再查第二权重维度

### 7. 修补型提示词（R1—R10）

```
【R1 去空话】
通读下文，找出所有无信息量的表述（如"加强领导""高度重视""进一步提高"）
并替换为具体动作、责任方或可检验的标准。保留原意，不要扩写。

【R2 补要素】
按{{文种}}的必需要素逐项核对下文，列出缺失项，并告诉我每一项需要我补充什么信息。
不要自行编造填补。

【R3 量化改写】
把下文所有模糊表述改成可量化、可考核的：
"明显提升" → 给出应有基期值与目标值的位置并标【待补充】；
"部分单位" → 明确是哪些；"尽快" → 明确日期。改不了的标【待补充】。

【R4 压缩篇幅】
把下文压缩到{{ }}字，保留全部事实、数据、责任单位与时限，
删掉重复表述、过程性铺陈与套话。不要删要素。

【R5 扩充篇幅】
把下文扩写至{{ }}字。只允许基于我提供的素材展开（细化做法、补充措施、展开论证），
不得新增素材之外的任何事实与数据，需要新事实的地方标【待补充】。

【R6 换语气】
把下文语气改为{{党委 / 政府 / 国企 / 事业 / 基层}}口径（详见 Y1—Y5），
只调语气与站位，不改事实与结构。

【R7 去 AI 味】
通读下文，消除 AI 写作痕迹：去掉过度对仗的排比堆砌、空洞形容词、
"不是……而是……"式套句、机械过渡词、公式化结尾。
改为公文平实表达，保留全部事实与数据。

【R8 翻译成大白话】
把下文改写成通俗易懂的版本，用于向{{群众 / 村民 / 基层干部}}讲解。
保留全部事实与数据，只换表达，不改政策口径。

【R9 标题优化】
为下文拟 3 个标题，按"发文机关 + 事由 + 文种"三要素规范，
并说明各标题的适用场景（正式行文 / 内部件 / 上报件）。

【R10 段落改写】
把下文第{{ }}段改写得更{{简练 / 有力 / 平实 / 庄重}}，改后附上原句与改句对照，
并说明为什么这么改。
```

### 9. 提示词写法本身的禁忌

| 禁忌 | 后果 | 正确做法 |
|---|---|---|
| 只说"帮我写个通知" | 参数全靠 AI 猜，写出通用废话 | 至少给单位性质、文种、素材三项 |
| 让 AI 边审边改 | 改了什么说不清，责任链断 | 质检与改稿分两次对话 |
| 说"数据你估一下" | 编造，真实性红线 | 标【待补充】，后填 |
| 把涉密材料整篇粘贴 | 输入侧泄密 | 先脱敏，只给结构与可公开表述 |
| 用"最好写得大气一点"这类模糊指令 | AI 堆形容词，公文味尽失 | 用 Y1—Y5 语气指令或指明参照 |
| 一次要求又长又好又全 | 顾此失彼 | 先出骨架，再分段扩写 |
| 不说明给谁看 | 语气与站位全错 | 必填"场合 + 听众 + 我的角色" |

### 10. 待补充项

| 待补项 | 用途 | 来源 |
|---|---|---|
| 真实范文样本 | 用于 Few-shot（给 AI 看样例再写），效果提升最显著 | 使用方收集（见内容资产收集清单） |
| 各单位惯用口径与术语表 | 提示词中替换为该单位用语 | 使用单位 / 客户 |
| 本单位保密与脱敏细则 | 安全类提示词本地化 | 使用单位保密部门 |
| 提示词效果回流记录 | 哪条提示词好使、哪条常返工，持续迭代 | 使用过程积累 |
