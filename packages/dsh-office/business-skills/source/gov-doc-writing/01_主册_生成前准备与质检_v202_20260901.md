### 0. 一句话原则

**没做完生成前四步，不准动笔。**
政治初检不过、要素不齐、事实没要到、语境没路由——写出来的就是"看着像公文、实则不合格"的稿子。

### 2. 生成前四步主流程

> 🔒 **步数口径统一（v2.0.1）**：本手册主流程为**四步**（①政治表述初检 ②要素矩阵核对 ③事实索取清单 ④差异化路由）。
> **"确认公开度（L1—L4）"是独立的第 0 步必问项，不计入四步**——它属 SKILL 第 0 步，规则见本册第 3 编 §5。
> 全包所有文件引用本手册时一律称"**四步**"，不得写成"五步"；SKILL 统一调用提示词模板已同步改正。

#### 第①步　政治表述初检（必做，先于一切）

读 第 2 册第 2 编《L0 政治表述规范库》：

- [ ] 核心提法一字未改（1.1—1.3 表：指导思想、固定提法、会议届次）
- [ ] 机构规范简称（2.1—2.3：首次用全称，无生造简称）
- [ ] 领导人职务排序（3.1—3.2：职务完整、排序正确、卸任者不加职务）
- [ ] 禁用词红线（4.1—4.5：尤其"亲自""老板""隆重召开"、极端评价、网络用语）
- [ ] 涉港澳台、民族宗教红线（5—6 节，**不得变通**）

> **用途**：起草时直接套用标准表述，避免生成后再大面积返修。生成后还要用 第 2 册第 1 编第 10 节质检清单 + 第 2 册第 2 编第 7 节再做一轮**终检**。
> **初检速查优先级**：时间紧时至少过 §1.2 固定提法 + §4 禁用词（最高频触碰点）；§1.1 / 1.3 / 2 / 3 / 5 / 6 按文种风险按需查阅，不必每次全读。
> **终检标准**：生成后以《公文质量检查手册》六维清单为统一标尺（见 SKILL 第 4 步）。

#### 第②步　要素矩阵核对（确定文种后立即做）

读 第 3 册第 2 编《L1 要素矩阵与事实索取清单》 第一部分：

- [ ] 用"七要素速查"（依据背景 / 目标任务 / 举措 / 责任 / 时序 / 保障 / 检验）确认本文种的**必需要素（●）**
- [ ] 对照"法定文种矩阵 / 事务文书矩阵"找出**最易漏项**
  - 请示 → 拟办意见 + 一文一事
  - 报告 → 存在问题（只报喜不报忧）
  - 通知 → 责任单位 + 完成时限
  - 意见 → 政策措施可操作性
  - 工作方案 → 责任分工表 + 阶段节点
  - 汇报 / 总结 → 真实问题（只讲成绩）
- [ ] 把"必需要素"列成勾选清单，生成时逐块对齐

#### 第③步　事实索取清单（发给用户填，铁律）

读 第 3 册第 2 编《L1 要素矩阵与事实索取清单》 第二部分，按文种取对应清单模板，发给用户填写。

- [ ] 用户填多少，AI 写多少
- [ ] **未填项一律标 `【待补充：需要什么】`，绝不用看似合理的内容填补**
- [ ] 用户说"你看着写"，也至少索要关键数据（金额 / 指标 / 文号 / 拟办意见）

#### 第④步　差异化路由（按单位性质 × 文种指向 L2 / L3）

完成前 3 步后，按下表定位"说谁的话、站在谁的位置"，再读 第 3 册第 3 编《L2_L3 语境与角色层》 对应章节：

**单位性质 → L2 章节**

| 单位性质 | 读 L2 | 核心提醒 |
|---|---|---|
| 党委机关 | 2.1.1 | 党建 + 业务融合，不得把党委写成政府 |
| 政府及政府部门 | 2.1.2 | 必有量化指标、责任分工、完成时限 |
| 专业业务部门（如自然资源、生态环境、市场监管等） | 2.1.3 | 专业术语不得误用；业务数据须准确 |
| 事业单位 | 2.1.4 | 公益属性，忌行政命令口吻 |
| 国有企业（含平台公司） | 2.1.5 | 党建 + 经营双线；重大事项须党委会前置 |
| 基层自治组织（村集体 / 社区） | 2.1.6 | 通俗易懂，重要事项须经会议决议 |
| 园区管委会 | 2.1.7 | 招商 / 项目落地口径，忌数据虚报 |

**角色 → L3 章节**

| 角色 | 读 L3 | 核心提醒 |
|---|---|---|
| 代笔（文秘为领导写） | 3.1 | 姓"公"不姓"私"，每句有依据 |
| 领导本人（一把手 / 副职 / 部门负责人 / 新任） | 3.2 | 站位高度不同，该讲与不该讲有别 |
| 个人（述职 / 对照检查 / 心得） | 3.3 | 第一人称，不足要真诚 |
| 基层工作人员 | 3.4 | 篇幅宜短，多具体事例数据 |

> 部门维度（办公室 / 党建 / 纪检 / 人事 / 财务 / 宣传）见 L2 第二部分；行文方向（上行 / 下行 / 平行）见 L2 第三部分，按需叠加。

## 0. 六维质量模型（先记住这把尺子）

| 维度 | 内涵 | 典型硬伤 |
|---|---|---|
| **政治性** | 站位正确、提法规范、机构名称准确、与党中央保持一致 | 政治表述不准确、机构名称写错、提法过时 |
| **合法性** | 主体有权限、程序合规、依据充分、不抵触上位规定 | 越权发文、程序缺失、依据文号错误 |
| **真实性** | 数据、事例、文号、人名、地名、时间准确 | 编造数据、文号不实、张冠李戴 |
| **逻辑性** | 结构完整、层次清晰、因果成立、论据与论点匹配 | 结构残缺、因果断裂、论据支撑不住结论 |
| **表达性** | 文种正确、格式规范、语言准确、文风得体 | 文种用错、格式要素缺失、标点数字错误 |
| **实效性** | 目标可考核、措施可操作、责任可追溯、时限明确 | 只有部署没有指标、只有任务没有责任单位、没有时限 |

> **安全性**是隐性第七维（涉密、敏感、隐私）。出问题即一票否决，不计入评分但优先排查。

## 1. 不同主体的维度权重（检查重点随主体变）

| 主体 | 第一权重 | 第二权重 | 特殊检查点 |
|---|---|---|---|
| **党委机关** | 政治性 | 逻辑性 | 党建引领、干部工作、意识形态责任制、巡视巡察整改 |
| **政府部门** | 实效性 | 逻辑性 | 指标、项目、资金、时限缺一不可 |
| **国有企业** | 实效性 | 政治性 | **双线并行**：经营指标 + 党建引领；三重一大须经党委会前置 |
| **事业单位** | 实效性 | 表达性 | 公益属性、服务质量、群众满意度 |
| **基层自治组织** | 真实性 | 表达性 | 通俗具体、四议两公开、一事一议、集体资产处置须公示 |

**权重差异的实操含义**
- 给党委写稿：政治表述准确度 > 措施细腻度
- 给政府部门写稿：指标 / 责任 / 时限完备度 > 文采
- 给国企写稿：经营数据扎实 + 党建表述到位，缺一不可
- 给基层写稿：宁可朴素不可官样，宁可具体不可宏大

## 2. 六维质检清单（生成后逐项自查，可勾选）

### 政治性（最高优先级，党委机关尤甚）
- [ ] 政治表述为当前标准提法（对照 第 2 册第 2 编《L0 政治表述规范库》§1）
- [ ] 党和国家机构名称规范完整（§2，首次用全称）
- [ ] 领导人职务与排序正确（§3）
- [ ] 无已停用 / 过时表述（§1.3 会议届次、"四个全面"最新项）
- [ ] 无不当简称或臆造提法
- [ ] 涉港澳台、民族宗教表述合规（§5—6，红线不可变通）

### 合法性
- [ ] 发文主体有此权限（不越权、不越级；部门未经授权不得向下级党委政府发指令）
- [ ] 需经前置程序的已履行（党委会、政府常务会、职代会）
- [ ] 引用依据文号真实、现行有效
- [ ] 不与上位规定抵触

### 真实性（AI 红线，一票否决）
- [ ] 所有数据由用户提供并可溯源
- [ ] 所有事例真实发生
- [ ] 引用文件文号已核实
- [ ] 人名、地名、职务准确

### 逻辑性
- [ ] 结构完整（按 第 3 册第 1 编《L1 文种骨架》，第 3 册第 2 编要素矩阵必需要素齐全）
- [ ] 层次清晰（一、→（一）→ 1. →（1）规范）
- [ ] 因果成立（措施能支撑目标）
- [ ] 论据与论点匹配

### 实效性
- [ ] 目标可量化、可考核（对照 第 4 册第 3 编《量化指标体系库》）
- [ ] 每项任务有具体责任单位
- [ ] 有明确完成时限
- [ ] 保障措施具体（不只写"加强领导"）
- [ ] 有检验与考核安排

### 表达性（国标 + 第 2 册第 1 编第 10 节）
- [ ] 文种正确（对照 第 2 册第 1 编第 1 节 15 文种边界）
- [ ] 格式 18 要素齐全
- [ ] 标点、数字用法规范（第 5 册《国标原文补编》）
- [ ] 文风得体（符合主体语境，第 3 册第 3 编《L2_L3 语境与角色层》）

### 安全性（一票否决，速览 4 条）
- [ ] 不含涉密内容
- [ ] 不含个人隐私信息
- [ ] 不含未公开敏感数据
- [ ] 需标注密级的已标注

> ⚠️ **以上为速览，不是完整标尺**。安全性检查**一律按本册第 3 编 §8 排雷检查单**（输入侧 + 内容侧 + 公开度三段）执行，
> 命中红线 S1—S6 任一即退回脱敏或改写。本速览仅用于成稿后快速自问，**不得替代 §8**——两者并存时以 §8 为准。

## 3. 按权重驱动的终检顺序（提高效率）

生成后终检不建议六维平推，按"**先排雷 → 再合法性 → 再主体权重 → 后格式**"的顺序：

1. **真实性 + 安全性**（红线，一票否决，先排雷；安全性按本册第 3 编 §8 排雷检查单）
2. **合法性**（**所有文种必查**：发文权限、前置程序、依据文号、是否抵触上位规定。上行文请示、涉审批 / 涉资金 / 涉人事事项须优先细查）
3. **主体第一权重维度**（党委先查政治性、政府 / 国企先查实效性，见 §1 权重表）
4. **主体第二权重维度**（见 §1 权重表）
5. **表达性**（国标格式，第 2 册第 1 编第 10 节 + 第 5 册国标专项）

> **合法性为何单列在权重之前**：它回答的是"能不能发"，与主体性质无关——不论党委还是国企，越权发文、
> 依据文号不实、缺前置程序都是硬伤。原版本把合法性混在权重维度里，导致上行请示这类"合法性风险最高"的
> 文种反而没有固定检查位置，故 v2.0.1 单列一档。

> **示例**：给某主管部门写一份**请示**（上行文，主体权重：实效性第一、逻辑性第二）
> ① 真实性 + 安全性（排雷：数据可溯源、无涉密）→ ② 合法性（本机关有无请示权限、政策依据文号是否现行有效、
> 是否需经党委会 / 办公会前置审议）→ ③ 实效性（第一权重：事项是否一文一事、拟办意见是否明确）→
> ④ 逻辑性（第二权重：理由能否支撑事项）→ ⑤ 表达性（格式、结语是否要求批复）。

> ⚠️ **精简审时可压缩但不可省**：第 1 档（真实 + 安全）任何情况不得省；第 2 档合法性至少过
> "发文权限 + 依据文号"两项；第 3—5 档按主体与文种风险取舍。

## 4. 与生成前 / 生成后的衔接

- **生成前**：生成前准备手册第①步已做政治性初检；本手册的"实效性 / 合法性"要点可在索取事实时前置提醒（如"请提供可考核的指标""请提供审批 / 前置程序依据"）。
- **生成后**：SKILL 技能入口第 4 步终检，以本手册六维清单替换原 第 2 册第 1 编第 10 节纯格式清单，输出**分维度**自检结果。
- **交付**：说明每一维通过情况、待用户补充项、需核实项。

## 5. 红线重申

- **真实性、安全性**为隐性否决项，任一不通过即不合格。
- **政治性**对党委机关为第一权重，初检不过不许写。
- 六维检查不是走过场：每勾一项，必须能指出来源或依据；拿不准的标 `【待核实：…】`。

## 公文写作技能包 · 安全保密检查规则库

> **建立日期**：2026-09-01　**版本**：v1.0

### 0. 一句话原则

**写完不等于能发。任何一份公文在离开你手之前，都必须过一遍"能不能说、说到什么程度、对谁说"。**

公文泄密的三种典型后果，按严重程度递进：

| 层级 | 后果 | 典型触发 |
|---|---|---|
| 一级 | 法律责任（泄密、侵犯个人信息） | 涉密文件上网、公民身份证号 / 手机号批量公开 |
| 二级 | 政治与工作被动 | 未定稿的政策、未公开的敏感数据提前流出 |
| 三级 | 单位形象与信任损失 | 内部矛盾、未处理问题、具体人名被外部看到 |

### 1. 一票否决红线（S1—S6）

**命中任一条即整篇不得交付，退回脱敏或改写，不做"权衡"。**

| 编号 | 红线 | 判定要点 | 处置 |
|---|---|---|---|
| **S1** | **国家秘密不得进入非涉密载体 / 非涉密渠道** | 任何标有密级（绝密 / 机密 / 秘密）的内容、派生密件内容 | 立即停止在外部工具中处理；退回保密渠道办理 |
| **S2** | **不得把涉密内容输入非涉密 AI / 外部服务** | 见 §2.4 输入侧风险（本场景最高频、最易忽视风险点） | 立即中止；不得继续生成 |
| **S3** | **个人信息未脱敏不得公开** | 身份证号、手机号、家庭住址、银行账号、健康信息、行踪轨迹、未成年人信息 | 脱敏或删除，见 §4 |
| **S4** | **未公开敏感事项不得写入可扩散文稿** | 未定稿政策、未报批数据、人事酝酿、纪检线索、招标标底、谈判底线 | 删除或改为内部限定稿 |
| **S5** | **内部矛盾与未处理问题不得外流** | 未形成结论的分歧、上级批评原文、内部通报的负面个案 | 删除或降级为内部稿 |
| **S6** | **涉密载体流转信息不得写明** | 定密 / 解密时间、知悉范围名单、保密要害部位、密码通信设备参数 | 一律删除 |

> **操作提示**：红线判定只看"内容属性"，不看"领导口头同意"。口头同意不构成脱密依据。

### 2. 国家秘密识别与处理

#### 2.1 密级与标志

| 密级 | 标志格式 | 保密期限上限 | 公文场景处理 |
|---|---|---|---|
| 绝密 | `绝密★30年` | 30 年 | **不得在非涉密环境处理任何片段**，包括转述与摘要 |
| 机密 | `机密★20年` | 20 年 | 同上 |
| 秘密 | `秘密★10年` | 10 年 | 同上 |
| 工作秘密 | 一般标 `内部` / `内部资料 注意保管` | 无统一法定期限 | 不得公开；内部按单位规定管理 |
| 不予公开 | 政府信息公开的答复类别之一 | — | 按《政府信息公开条例》处理，不得主动上网 |

#### 2.2 识别动作（三问三查）

动笔前与定稿前各做一次：

```
① 查标志：正文、附件、页眉页脚、文件头有无密级标志？
② 查来源：素材来自哪个文件 / 会议？该文件是否标密？
③ 查性质：内容是否属于"泄露后会损害国家安全和利益"的事项？
④ 问定密：本单位是否已就该事项正式定密？（未定密 ≠ 可以公开）
⑤ 问范围：这份稿的阅读范围是"内部""限定范围"还是"可公开"？
⑥ 问先例：同类事项过去是内部稿还是公开稿？有无既定口径？
```

> **关键认知**：**没有密级标志，不等于不涉及国家秘密**。派生事项、未定密但敏感的事项，按"存疑从严"处理。

#### 2.3 派生与转述同样受限

以下行为均**不降低**保密要求：

- 复制、摘录、引用涉密文件的段落
- 用自己的话**转述**涉密内容
- 把涉密数据做**比例换算 / 单位换算**后呈现
- 把涉密内容放进附件、图表、注释、举例
- 在"删掉敏感信息后"仍可反推原值的组合信息

> **公文高频坑**：写总结时习惯"举一个例子说明"，而例子本身可能就是敏感个案。举例前先过 S3 / S5。

#### 2.4 输入侧风险（本场景最高频）

**用 AI 辅助写公文时，泄密往往发生在"把材料粘进来"这一步，而不是"稿子发出去"那一步。**

| 风险动作 | 为什么危险 | 替代做法 |
|---|---|---|
| 直接粘贴涉密文件原文求改稿 | 涉密内容进入非涉密服务 | 只粘**结构**与**可公开表述**，事实部分留 `【待补充】` |
| 粘贴含真实姓名 + 身份证号 / 手机号的表单 | 个人信息泄露 | 先脱敏为"张三""138****0000" |
| 粘贴完整内部会议纪要求整理 | 未公开事项外流 | 先删去酝酿过程、分歧意见、具体人名 |
| 上传含未公开财政数据、标底的表格 | 敏感数据外流 | 用**示意性数值**替代，正式数据回填在单位内部完成 |
| 把整本内部制度手册作为参考资料上传 | 一次性外流大量内部信息 | 只摘取与本次文稿直接相关的条款 |

> **给客户的标准提示语**（可直接复制给用户）：
> "请只提供可公开的内容。如涉及涉密、未公开事项或公民个人信息，请先自行脱敏（姓名用'某某'、号码打星号），或只描述事项性质、不提供原始材料。数据部分可留空，我会标【待补充】，您回填。"

### 4. 个人信息与隐私脱敏规则

#### 4.1 敏感个人信息（从严处理）

依据《个人信息保护法》口径，以下属于敏感个人信息，**公文场景下默认脱敏或删除**：

```
· 生物识别信息（人脸识别、指纹、声纹）
· 宗教信仰与特定身份
· 医疗健康信息（诊断、病史、检查结果）
· 金融账户信息（银行卡号、账户流水）
· 行踪轨迹信息
· 不满十四周岁未成年人的个人信息（一律不得公开姓名、学校、照片）
```

#### 4.2 脱敏规则表

| 信息类型 | 原文 | 脱敏后 | 备注 |
|---|---|---|---|
| 身份证号 | `510***********1234` | `510***********0000` 或 `某某` | 公示类一般只保留前 6 位 + 后 4 位打星，或直接不列 |
| 手机号 | `13812345678` | `138****5678` | 名单类公示通常不列手机号 |
| 姓名（个案 / 举报人 / 未成年人 / 患者） | 张某某 | `张某` / `某同志` / `某某` | 表彰类经本人同意可实名 |
| 家庭住址 | 某某市某某区某某路 12 号 3 单元 | `某某区` | 公示类只到乡镇 / 街道 |
| 银行账户 | `6222 **** **** 1234` | 只保留后 4 位或不列 | 涉补贴公示按单位规定 |
| 健康信息 | 具体病名、诊断 | `身体原因` / `特殊情况` | 救济类材料须从严 |
| 单位 + 职务 + 姓名组合 | 某某局某某科科长张三 | 视场景保留"某某局"或"某科室负责人" | 组合信息可反推个人，须一并评估 |
| 照片 / 影像 | 含人脸、车牌、门牌 | 打码或不附 | 现场照片尤易漏 |

#### 4.3 组合信息风险（易漏）

**单项脱敏了，组合起来仍能锁定到人**——这是公文最常见的漏点。

| 组合 | 风险 |
|---|---|
| 单位 + 职务 + 姓氏 | 小单位内可锁定唯一人 |
| 村 + 金额 + 事项 | 可锁定具体补贴对象 |
| 时间 + 地点 + 事件描述 | 可锁定当事人 |
| 罕见姓氏 + 罕见病种 / 罕见荣誉 | 可锁定个人 |

> **判定口诀**：**三个以上维度能唯一锁定一个人的，就要再脱一层。**

### 5. 公开度分级与文种对应

> 决定"能写到什么程度"的关键不是文种，而是**这份稿最终会被谁看到**。

| 公开度 | 定义 | 允许内容 | 禁止内容 |
|---|---|---|---|
| **L1 涉密** | 标有密级 | 按保密渠道办理 | **不得在本技能 / 任何外部 AI 环境处理** |
| **L2 内部** | 限本单位 / 本系统 | 未公开数据、内部问题、具体人名职务、内部评价 | 不得上网、不得对外转发、不得进外部 AI 生成环节（除非已脱敏） |
| **L3 限制公开** | 可对外但需审定 | 经批准的成果、已公开的统计数据、经同意的实名 | 未审定的结论、未脱敏个人信息 |
| **L4 主动公开** | 面向社会 | 已审定的政策、已公开数据、脱敏后的案例 | 除上述之外的一切内部信息 |

**文种 → 默认公开度**（未特别说明时按此判定，须向用户确认）：

| 文种 | 默认 | 提醒 |
|---|---|---|
| 公示、通告、公告 | L4 | 个人信息脱敏最易出问题 |
| 通知（政策类） | L4 | 涉内部实施细则的走 L2 |
| 方案、实施意见 | L4 / L3 | 责任分工含具体人名时评估 |
| 报告（上报） | L2 | 上行文常含未公开数据 |
| 请示 | L2 | 拟办意见属内部信息 |
| 会议纪要 | **L2** | 最易外流的文种，见下 |
| 讲话稿 | L2 起 | 定稿前一律按 L2 管 |
| 总结、汇报 | L2 起 | 问题部分常涉内部信息 |
| 通报（批评类） | L3 | 未经程序不得公开 |
| 国企经营分析 | **L2** | 财务数据未披露前均属内部 |

> **会议纪要特别提醒**：纪要天然包含"谁说了什么、谁反对、谁负责"——这是**内部信息密度最高**的文种。整理纪要时默认按 L2 管，对外提供纪要须逐条审定。

### 6. 脱敏操作四法

| 方法 | 适用 | 示例 |
|---|---|---|
| **删除** | 完全不可外露 | 整段删去酝酿过程 |
| **概括** | 可说性质不可说细节 | "个别单位推进不力" → "少数单位进度滞后"（若仍敏感则"部分单位"） |
| **模糊** | 需要体现规模不需精确 | "投资 3.7 亿元" → "投资约 3 亿元"（未公开时改为"投资规模较大"或删除） |
| **代称** | 需要指代但不点名 | 人名 → "某同志"；单位 → "有关单位" |

**脱敏后仍须复核的三点**：

1. 是否还能通过剩余信息**反推**出被删内容？
2. 脱敏后是否影响了文稿的**可用性**（要素矩阵要求的责任单位、时限是否还清楚）？——可通过"责任单位写到部门层级、不写到个人"兼顾。
3. 脱敏是否改变了**事实本身**？——脱敏不等于改写事实，真实性维度仍要守住。

### 7. 常见安全错误病例（J 类，与病文纠错库 B1—B14 同体系）

| 编号 | 病例 | 错在哪 | 改法 |
|---|---|---|---|
| **J1** | 公示名单列全身份证号 | 个人信息未脱敏，S3 | 保留前 6 位 + 后 4 位打星，或只列姓名 + 村组 |
| **J2** | 总结中"如某某同志反映的某某问题" | 信访人信息外露，D 类 | 删去姓名，改"部分群众反映" |
| **J3** | 招商方案直接写标底 / 底价 | 敏感数据外流，E 类 | 删除，改"按相关规定另行明确" |
| **J4** | 把未定稿的规划数据写进对外汇报 | 未公开决策外流，B 类 | 删除或标"以正式批复为准" |
| **J5** | 讲话稿引用上级未公开的批评原话 | 内部信息外流，S5 | 改原则性表述"上级指出……方面还需加强" |
| **J6** | 纪要照抄讨论中的分歧与反对意见 | 内部信息密度过高 | 只记议定事项，分歧不记入对外版本 |
| **J7** | 案例写明"某村某组某某，患某某病" | 组合锁定个人 + 健康信息 | 改为"某村一位群众"，隐去病名 |
| **J8** | 直接把涉密文件段落粘给 AI 求改写 | 输入侧泄密，S2 | 拆结构、留待补充，不粘原文 |
| **J9** | 通报批评直接点名并全文上网 | 未经程序公开 | 走审定程序，或改为内部通报 |
| **J10** | 附上含人脸 / 车牌的现场照片 | 影像未脱敏 | 打码或更换照片 |
| **J11** | 写明清退 / 处分的具体金额与责任人姓名 | C / D 类 + 组合锁定 | 只写处理结果，不写细节与姓名 |
| **J12** | 国企经营分析引用未披露的债权债务明细 | E 类 | 用已披露口径或示意值 |

### 8. 排雷闸门接入（SOP §3 安全专岗检查单）

**执行时点**：拟稿团交稿后、六维审核团之前，与真实性专家**并行且同时**判定，任一不过即退回。

```
【安全排雷检查单 · 逐条打钩，全过才放行】

一、输入侧（回顾本次用户提供的原始素材）
□ 未见明显涉密标志内容被粘贴进来
□ 未见未脱敏的身份证号 / 手机号 / 住址 / 银行账号
□ 未见未公开的会议纪要、内部通报原件
□ 如发现上述内容 → 已提示用户风险，且未在生成中扩散

二、生成内容侧
□ 无涉密事项及可反推的转述（S1 / S6）
□ 个人信息已脱敏，且组合信息不能唯一锁定到人（S3 / §4.3）
□ 无未公开政策、人事酝酿、纪检线索、标底底价（S4）
□ 无内部矛盾、未形成结论的分歧、上级批评原话（S5）
□ 数据与案例可溯源至用户已提供或已公开来源

三、公开度与范围
□ 已确认本稿的公开度级别（L1 / L2 / L3 / L4）
□ 文稿密级标志 / "内部"标识与该级别一致
□ 文末注明印发范围、可否公开（如需）

四、输出结论
□ 通过 → 放行至六维审核团
□ 退回 → 列出命中条款（S 编号）+ 具体位置 + 处置建议
```

### 9. 客户通俗版安全提示（可直接发给客户）

```
【保密提示 · 请先看这几条】
```
