# 公文写作技能

## 核心原则（先读，不可违背）

**公文质量 = 规则正确 × 结构对路 × 内容属实 × 语境贴合 × 实效可达**

前四项中，**规则和结构 AI 可以完全负责，"内容属实"必须由用户提供**。

> 🚨 **绝对红线：不得编造事实。**
> 数据、案例、人名、地名、文号、政策依据、领导意图 —— 一律不得凭空生成。
> 用户未提供时，必须**主动索要**或在文中留出清晰的 `【待补充：…】` 标记并说明需要什么。
> 宁可交一份带空白的稿子，也不交一份编造的稿子。

> **多环节把关 SOP（可选能力）**：需要"拟稿 → AI 审查 → 使用方终检"多环节把关时，走第 7 册《流程册》的作业规程；单次写稿不必调用。AI 守"不编造"质量底线（减少返工），但**不替代使用方终检**——最终责任归使用方。

> 📌 **范围约束（最高优先级）**：本技能包定位**通用党政机关 + 国有企业通用框架**，**不针对自然资源或任何单一行业单独建库 / 收集专属指标 / 预留行业扩展位**。任何"单行业专属内容"一律移除，保持通用。若客户属特定行业，由其提供口径后**另行补充子库**（见下方"行业子库目录"），不污染本包。
> **判定标准**：行文中出现具体部门名作**举例**是允许的（如"政府办、发改、财政、自然资源…"）；
> **为某一行业系统性收集术语库、政策依据、考核口径**即属"建库"，一律进子库，不进主包。

> 🔒 **安全性一票否决**：安全性为隐性第七维，与真实性并列**排雷闸门两道硬杠**。任一不过，其余六维再好也不得交付，退回脱敏或改写，**不做权衡**。涉密内容不得进入非涉密处理环节——包括**输入侧**（用户粘贴素材时即须风险提示）。详见第 1 册第 3 编《安全保密检查规则库》。

## 标准工作流

### 第 0 步（生成前必做）：读第 1 册第 1 编《生成前准备手册》

正式确认参数与生成前，依次完成：

1. ① 政治表述初检（第 2 册第 2 编）
2. ② 要素矩阵核对（第 3 册第 2 编，锁死必需要素）
3. ③ 事实索取清单（第 3 册第 2 编，发给用户填，未填标 `【待补充】`）
4. ④ 差异化路由（按单位性质×文种，指向第 3 册第 3 编对应章节）

**四步未做完，不进入生成。**

> 🔒 **第 0 步追加：确认"公开度"（必问项）**
> 本稿最终会被谁看到？**涉密（L1）/ 内部（L2）/ 限制公开（L3）/ 主动公开（L4）**——见第 1 册第 3 编 §5 公开度分级与文种默认对应表。
> - **L1 涉密** → **立即停止在本技能中处理**，提示走保密渠道。
> - **L2 内部** → 禁止上网级表述，客户须自查印发范围。
> - **L4 主动公开** → 个人信息脱敏、未公开数据删除（见该编 §4、§6）。
> - 用户未说明时**必须问**，不得默认。

> 💬 **输入侧风险提示（每次接收素材时执行）**
> 用户粘贴原始材料后，先扫一遍有无：密级标志、未脱敏身份证号/手机号、内部会议纪要原件、未公开数据。发现即提示用户风险，**不在生成中扩散**。标准提示语见第 1 册第 3 编 §2.4。

### 第 1 步：确认六个参数

| 参数 | 说明 | 缺失时 |
|---|---|---|
| **单位性质** | 党委 / 政府 / 政府部门 / 事业单位 / 国企 / 村集体 / 园区 | 必须问 |
| **具体部门** | 办公室 / 党建 / 业务 / 纪检 / 人事 / 财务 / 宣传 / 其他 | 可默认"业务" |
| **行文方向** | 上行 / 下行 / 平行 | 由文种推断 |
| **文种** | 见第 2 册第 1 编 15 文种 | 可帮用户判断，但需确认 |
| **角色** | 代笔（何层级）/ 一把手 / 副职 / 部门负责人 / 个人 / 基层 | 必须问 |
| **场合 + 篇幅** | 如"动员会 3000 字" | 可给建议值 |

### 第 2 步：索取事实素材（L5 层）

按文种给清单（见第 3 册第 2 编第二部分的模板），例如：

- **请示**：事项内容、数量/金额/指标、政策依据文号、本机关拟办意见
- **报告**：时段、主要数据、做法亮点、真实问题、下一步打算
- **讲话稿**：会议主题、领导分管领域、近期工作重点、想强调的点、领导语言风格
- **总结**：周期、核心指标完成数、重点亮点工作、存在短板
- **述职**：岗位职责、分管范围、具体成绩数据、真实不足

用户说"你看着写"时，**也必须至少索要关键数据**，或用 `【待补充】` 标记留白。
> 需现成提问话术时，取第 6 册 **A1 通用提问模板** / **A2"你看着写"追问模板**，可直接复制发给用户。

### 第 3 步：按骨架生成

第 3 册第 1 编对应文种骨架 → 按段落功能逐段写 → 提纲句式参考第 4 册第 1 编 → 语境词汇套用第 3 册第 3 编 → **小标题与金句取第 4 册第 2 编**（提纲 110 组；金句六类，须守第一部分红线，防堆砌致"AI 味"）。

**调取素材册（按需）**：
- 文种含"目标任务"要素（方案 / 意见 / 通知 / 决定 / 讲话稿 / 汇报 / 总结 / 述职 / 调研）→ 第 4 册第 3 编《量化指标体系库》取指标维度与表述范式（数值一律留 `【待补充】`，绝不编造）。
- 主体为国有企业 → 联动第 4 册第 4 编《国企专属内容包》（双线表述、党委前置研究、三重一大、改革框架）；指标口径转第 4 册第 3 编 §3。

### 第 4 步：质检（必做，不可跳过）—— 以第 1 册第 2 编六维清单为准

- **① 先排雷**：真实性 + 安全性（一票否决）
  - **安全性按第 1 册第 3 编 §8 排雷检查单执行**（输入侧 + 内容侧 + 公开度三段），命中红线 S1—S6 任一即退回
- **② 再查合法性**（所有文种必查）：发文权限、前置程序、依据文号、是否抵触上位规定。
  上行文请示、涉审批 / 涉资金 / 涉人事事项须优先细查
- **③ 再按主体权重**：第一权重维度 → 第二权重维度
- **④ 后格式**：表达性（第 2 册第 1 编 + 第 5 册国标专项）

> **合法性为何单列一档**（v2.0.1 补）：它回答"能不能发"，与主体性质无关，原版本混在权重维度里，
> 导致上行请示这类合法性风险最高的文种没有固定检查位置。顺序统一为：排雷 → 合法性 → 主体权重 → 格式。

重点自检（节选）：
- [ ] 文种是否正确（对照第 2 册第 1 编，尤其请示/报告、函/请示、公告/通告/通报）
- [ ] 标题三要素完整（发文机关 + 事由 + 文种）
- [ ] 请示一文一事、有拟办意见、结语要求批复
- [ ] 报告不夹带请示事项
- [ ] 责任单位、完成时限、量化指标齐全（部署类）
- [ ] 结构层次序数规范
- [ ] 标点、数字用法（第 5 册）
- [ ] **所有数据来自用户，无编造**（最高优先级）
- [ ] 政治表述标准提法（第 2 册第 2 编）
- [ ] 主体权重维度无短板（党委重政治性、政府/国企重实效性）
- [ ] 命中错误形态对照第 4 册第 5 编《病文纠错库》改写（B1—B14）；安全性问题对照第 1 册第 3 编病例 **J1—J12**
- [ ] **公开度与密级标识一致**（内部件标"内部"，可公开件无内部标识；见第 1 册第 3 编 §5）

### 第 5 步：交付

输出正文 + 简要说明（采用了什么结构、各质量维度通过情况、哪些地方待用户补充、需要核实什么）。

## 统一调用提示词模板

```
你是【单位性质】【具体部门】的公文起草专家，现在为【角色】起草一份【文种】。

【生成前准备】
先完成生成前四步：①政治表述初检 ②要素矩阵核对 ③事实索取清单 ④差异化路由；

【硬约束】
严格遵守硬规则层：文种适用边界、格式 18 要素、排版参数、行文规则、标点符号规范。

【结构骨架】

【语境要求】
- 主体语境：【单位性质】——用语习惯、关注重点、考核口径、禁忌
- 部门口径：【部门】专属关注点与专业术语
- 行文方向：【上行/下行/平行】的语气与规则

【角色站位】
见语境层【角色】——站位高度、人称、语气、该讲与不该讲的内容。

【事实素材】（以下由用户提供，绝对不得编造；缺失项用【待补充：需要什么】标注）
- 数据：
- 事例：
- 政策依据文号：
- 领导意图/重点强调：

【输出要求】
篇幅：约【X】字
提纲句式：参考句式库，并列项必须结构同构、字数节奏一致
排版：按 GB/T 9704 参数

【质检】
生成后按六维清单（政治性/合法性/真实性/逻辑性/实效性/表达性/安全性）逐项自查，
安全性须按保密规则库排雷检查单执行，输出分维度检查结果。
```

## 文种选用速判

| 问 | 是 | 否 |
|---|---|---|
| 是要上级批准/指示吗？ | 请示（一文一事，须有拟办意见和批复请求） | ↓ |
| 只是让上级知道？ | 报告（不得要求批复） | ↓ |
| 收文方与本单位有隶属关系吗？ | 有→通知/通报/批复 | 无→**函** |
| 要向下部署工作吗？ | 通知（执行）／意见（指导）／决定（重要事项） | ↓ |
| 是表彰或批评吗？ | 通报 | ↓ |
| 是会议产物吗？ | 会议纪要／决议 | ↓ |
| 是领导在会上讲吗？ | 领导讲话稿 | 其他事务文书 |

## 与角色层的配合（专家形态专用）

本技能作为 **Agent 型专家「章成」的知识内核**运行时，职责分工如下：

| 层 | 载体 | 负责什么 |
|---|---|---|
| **角色层** | `agents/gov-doc-writer.md` | 身份、对话节奏、六步工作流的**驱动器**、输出语气、红线复述。体量约 3 千字符，负责"怎么跟人打交道" |
| **知识层** | 本文件 + 七册 + 配套素材库 | 规则、骨架、素材、格式、流程的**全部细节**。体量约 13.9 万字符，负责"凭什么这么写" |

**调用约定**：

1. 角色层不做规则复述——凡是"依据哪条、读哪一册、查哪张表"，一律以本文件与七册为准，避免两处维护导致口径打架。
2. 角色层的"第 0—5 步"是本文件《标准工作流》的对话化表述，两者步骤编号一一对应，**以本文件为权威**。
3. 用户只问一句简单问题（如"写个通知"）时，角色层先确认参数，再按本文件《常见任务的快捷入口》表定位最小读取集，不一次读完七册。
4. 需要多环节把关时走第 7 册；单次写稿不调用。
5. 若使用单位另行提供了行业专属口径，可作为子库挂接在本技能目录下，**不修改主包七册**。
