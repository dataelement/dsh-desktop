## 会议纪要来源与 r5 重写

`meeting-recap` 的原文来自用户提供的 `开源skill-185个 (1).zip`，此前本地评审把这份归档称为“Kimi 185”。归档清单、原 Skill 和 PR #424 的迁入内容已逐项比对；现有来源记录只能确认用户提供归档，Kimi 官方发布身份仍待核实。原 Skill 的 MIT 许可署名为 `meeting-minutes contributors`。公文写作 `gov-doc-writing` 才是用户提供的 WorkBuddy 公文 Skill。

r5 依据当前 DSH 需求重写会议纪要正文与结构校验器：已定事项、讨论建议、待决事项及后续改动分开；负责人、日期和优先级依据用户原文；未知字段标为待确认；相对日期保留原口径；行动项集中在一张表中。结构校验覆盖缺失字段、真实日期、重复任务和空表，事实仍由当前材料逐项核对。

会议纪要 DOCX 案例由本仓库生成器制作，归档本身没有提供这份 DOCX。r5 改为清晰的标题层级、约 2cm 页边距、浅色表头、细灰边框和可编辑段落 / 表格；配套 design.md 与 Skill 共同约束生成效果。

公文红色抬头是一张原始 DOCX 内嵌图片。Kit 的 Writer 编辑视图会显示图片边界，直接渲染该视图会把细灰框带入预览。r5 对 Word 统一使用官方 Kit 的 PDF 导出页面生成预览，沿用原始 DOCX 内容、版式和可编辑源文件。

官方基础依赖来自 deepseek-ai/deepseek-harness 的 `dsh-v0.2.0-rc.2`，保留 npm 依赖本身的许可文件。原有业务 Skill 的许可文本随安装资源分发。

## 工作汇报来源与 r10 优化

`work-report-writer` 从原 PR 收录的用户业务归档迁入，保留原 MIT 许可。本版按当前 DSH 需求重写日报、周报与阶段总结的材料整理、统计周期、状态与日期规则，按用户材料给出可核对的进度和交付依据，配合官方 `office-docx` 制作 Word。

r10 保留三份 Word 原生参考案例及三份 Excel 原生参考案例，补充 Word 用途分类。阶段工作总结、项目实施方案以完整的模拟项目结果重做，工作日报新增一页示例；会议纪要沿用现有内容。共同版式清理默认标题边框与副标题斜体，提供可编辑段落、重复表头、完整表格行及页码。用当前官方 Kit 导出 PDF 并渲染逐页检查。成品结构与版式提供参考；实际生成质量继续由用户在 DSH 使用真实材料验证。

用户于 2026-10-12 认可三页《发布会筹备对齐》Word 成品并要求采用。新的 `meeting-minutes` 由 DSH 内置 `meeting-recap`、官方 `office-docx` 和已配置模型实际生成，经同一 DSH 会话的内容与版式复核完成；原始材料为飞书官方演示妙记。本轮保留五个议题与十五项行动记录，案例原件作为唯一模板输入，原始转写与模型日志留在本地评估目录。

原件 SHA-256 为 `b6183bbe83637defb3efe220fbfba6ddc9e5070a1e42aacf1168f9040f0deb5a`，保存在 `sources/curated/meeting-minutes/example.docx`。配套 design.md 说明沿用原生标题、表格、相对期限和来源的方式。内置会议 Skill 根据实际复核结果明确日期依据、标题样式、文档网格、表格列宽和安装资源路径；“做同款”先取得当前修订的原生副本，再用当前用户材料替换示例内容。
