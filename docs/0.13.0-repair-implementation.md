# 0.13.0 问题修复实施记录

## 1. 基线与范围

本轮在 `V0.13.0` 开发，起点先同步 `origin/main` 的 `a170609`。产品约定见[团队对齐稿](https://app.coaligne.com/f/TEHD7KzVgU)。这是开发中的首轮实现，不代表发版或全部平台验收完成。

## 2. 已接入的路径

### 2.1 无法正常启动

系统识别到可执行动作后，仅显示本轮措施和「一键修复」，回退满足条件时与其并列；不要求选择 Profile 或逐个修复对象，不显示进度条。插件先升级并重新启动验证，再停用并验证。核心市场仅允许升级，不能自动停用；carrier 无法可逆停用时停止自动处理，不退回卸载。

已识别的配置规范化、旧工作流替换和兼容依赖修复复用现有带备份实现。无法确定安全转换的配置不自动重置。未知原因或修复用尽后提供安全模式维修 Agent。安全模式保留第三方插件辅助停用、错误提示和「重启并验证」。

### 2.2 正常启动后的局部错误

DSH 设置行右侧、手机图标旁提供扳手入口，在当前正常环境创建新的修复对话，不隐式启动安全环境、不重放原操作。没有可靠错误关联时由用户描述问题。

### 2.3 维修模式与连续性

两种环境使用内置 `desktop-repair` 预设和排查手册。进入时只准备短草稿并填入输入框，由用户编辑和发送；不会自动提交诊断指令，也不因没有可用模型而禁止打开会话。已有输入和附件保留，异步草稿不得覆盖用户改动。维修会话由 Harness 持有；独立状态文件只保存地址与初始化状态。安全维修在重启验证失败后恢复同一会话，稳定正常启动后结束该故障的维修指针，保留历史对话。

### 2.4 应用版本回退

更新安装前保存升级前实际应用版本、平台和架构。回退不接收 renderer 提供的任意旧版本，检查确切归档及下载元数据，复用 electron-updater 下载完整性校验；持久化失败及中断，阻止更新竞态替换目标。初始化早于首次 Harness 启动，恢复期间抑制常规自动检查；停止后台后安装失败时返回检修环境。

**尚未开放未经验证的数据降级。** 当前仓库没有可靠的数据格式兼容声明，默认返回 `data-compatibility-unverified`。兼容性判定及配套备份/恢复的真实平台验证补齐前，不把此底座宣称为可用的无损回退功能。历史安装没有升级前版本记录时也不猜测目标。

## 3. 内部记录

- `repair-journal.json`：动作前原子保存 pending，随后保存 restart/failed；以 renderer 健康和稳定启动确认 verified，不能只看后台 ready。按应用版本隔离；损坏记录阻止自动变更但保留维修入口。
- `application-rollback.json`：实际应用升级与回退目标/状态，不存放会话或配置快照。
- `recovery/repair-agent-sessions.json`：分别保存 normal/safe 维修会话地址，不保存凭据或完整对话。

Agent 工具沿用现有 Harness 权限；本轮未另建通用维修权限执行器。模式中的确认与备份指导不能替代将来对特定高风险动作增加的原生权限校验。

## 4. 验证与后续验收

已执行：`npm ci`（包含 postinstall）、`npm run typecheck`、`npm run build`、`npm test` 和 `git diff --check`。最终全量结果为 2239 项通过、1 项基线失败（226 个测试文件）。修复策略与持久状态/回退行为测试，以及真实 Harness 安全启动和修复预设会话创建/恢复通过。恢复页真实 Electron 检查覆盖 120 组语言、主题、尺寸和缩放组合。

全量回归曾发现 PPT 中文字体渲染测试失败，已在未修改的 `main a170609` 独立基线复现，属于本机现有基线问题；不通过改断言或跳过测试隐藏。

仍需完成 macOS/Windows 真实安装包的升级、回退、重启验证与连续故障端到端验收。Windows 原生安装结果不能用 macOS 上的逻辑测试代替。回退的数据兼容与备份恢复策略是开放该入口的前置条件。

## 5. 交互修订

- 移除独立的「维修 Agent」文字行，在 Settings 右侧并列放扳手和手机图标，保留键盘访问、提示与忙碌/错误反馈。
- 使用 session-scoped Harness `inputActions` 预填编辑器，get/ack 草稿 IPC 校验主窗口、main frame、session 与 token；无自动 `session/prompt` 调用。
- 一键修复后仍无法启动，保留明确选择页：可以执行下一轮可用修复、条件可用时回退，或主动选择安全模式维修 Agent。回退/安装失败同样返回选择，不自动打开 Agent。
- `dsh-client-ui-sidebar@0.2.1-rc.2` 最小补丁新增 `sidebar.settings.action`：root/list、仅接收 `wide`，用于 Settings 旁紧凑图标，默认无贡献项；旧 `sidebar.footer.action` 位置和语义不变。显式布局容器避免 Settings 的满宽按钮挤出图标。上游提供同位置等价 slot 后可删除此新增接缝。
- 已验证 Sidebar patch 在临时副本中 reverse/apply 往返完全一致；入口、草稿、附件/输入保护与显式选择行为有回归测试。
- 一键修复正常启动后恢复进入维修前的普通导航；兼容旧维修会话导航指针，保留维修历史和草稿，避免成功后仍显示维修模式。
- 安全模式维修沿用独立 Profile 与第三方插件隔离，保留左下角安全提示、管理插件和退出安全模式动作；普通环境维修不展示安全模式提示。扳手与手机图标使用统一视口、尺寸和中心对齐。
- 最新交互：安全状态卡仅保留说明与退出动作。启动恢复页先说明无法启动，再引导查看可尝试的方案；独立折叠区列出插件升级版本或停用对象。回退应用版本放左侧，一键修复放右侧；回退未满足开放条件时保持可见、禁用，并就近说明原因。方案详情与技术诊断抽屉分开，展开不触发修复。
- 后续界面修订：报错详情改为正文下方独立原位展开，不再使用右侧抽屉或拖拽调整宽度；页头、提示条、正文和操作区共用边界，主按钮右对齐。“让 Agent 帮我修”沿用显式选择，未知故障文案说明进入维修 Agent 模式后将在安全模式下继续排查问题。
- 最新流程校正：只要仍有已知修复手段，就只展示一键修复和应用回退，不因一次修复失败提前展示 Agent；未知问题、已知手段耗尽或回退失败后才提供安全模式维修 Agent，仍需用户主动选择。报错详情收拢为标题后的信息图标，悬停、聚焦或点击查看，保留日志入口。
- 主进程同样按当前修复方案校验 Agent 动作，旧页面残留请求不能绕过已知问题分流。修复步骤异常使用中性“请选择下一步处理方式”，不在仍有后续方案时提前引导 Agent。

## 6. 应用回退交互与演示边界

新增 `ApplicationRollbackFlow` 编排确认、取消、进度与结果；其 IPC 只接受当前主窗口中精确回退页面、主 frame 和对应阶段的动作。进行中拒绝重复提交，关闭窗口中断 UI 等待并屏蔽晚到结果。新页面列入打包资源。

正式回退有资格时先确认，再调用既有 updater 精确回退；数据兼容性 gate 保持关闭，未把模拟结果当成真实安装包降级验收。开发成功演示只处理专用 Profile 的 owned 故障插件，实际验证普通核心服务启动并由用户继续打开界面；失败演示返回未知问题选择页，Agent 仍需用户主动选择。模拟过程与实际未改变的应用版本均在页面中明确标注。
