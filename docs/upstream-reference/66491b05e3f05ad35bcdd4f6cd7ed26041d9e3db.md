# 官方 Desktop 基准观察

只记录 2026-11-05 在这台 Mac 上对未修改官方树的构建和启动。官方源码没有进入本仓库。Windows 没有跑。

- 来源：`deepseek-ai/deepseek-harness` tag `dsh-v0.2.2-rc.1`，commit `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`。
- 机器：macOS arm64，Node v26.0.0，pnpm 11.28.5。克隆在仓库外的临时目录，用冻结锁文件安装。
- 安装时 SheetJS 的 CDN 包超时。核对压缩包哈希后放进本机 pnpm store，再以离线方式装完。这是本机网络问题，不是改过官方锁文件。

## 构建

官方开发启动先跑仓库根的 `pnpm run build:artifacts`。这次 8 个门都过了，约 70 秒：原生 addon、Host Typert、Host 编译、Host bundle、Desktop bundle、客户端编译、客户端 bundle、Web 构建。记录了 366 个客户端产物。

产物在官方树里，不在本仓库：

- `apps/desktop/lib/main.js`
- `apps/desktop-host/lib/index.js`

没有再单独跑 desktop 包的 `tsc -b && bundle`。上面的 Desktop bundle 门已经写出 `lib/main.js`。

## 启动

用 `pnpm run start:desktop`（跳过再次构建）。显式清掉了 `DSH_HOME`，并关掉自动 DevTools。调试端口改成 19229、19222、19230，避免碰到本机其他进程。

第一次启动在准备 primary runtime 时按官方默认 300 秒超时中断，日志是 `The operation was aborted due to timeout`。当时只有 Node 压缩包进入了开发下载缓存。把锁文件里的 macOS arm64 Python 压缩包和 wheel 先下进同一缓存后，第二次启动通过了 Office runtime 检查，并打印了 pnpm `11.28.5`。

启动器打印的路径：

- `DSH_HOME`：官方树内 `apps/desktop/.desktop-build/development/home`
- Electron `userData`：同一开发目录下的 `electron-user-data`
- primary runtime：`apps/desktop/.desktop-build/targets/mac-arm64/runtime/primary-runtime`

本机 `~/.dsh` 的修改时间仍是 2026-09-30，这次没有写它。用户 Documents 里已有的 `deepseek-harness/default-workspace` 修改时间仍是 2026-10-30，这次没有改那个目录。

进程：

1. 开发用的应用包是 `.desktop-build/development/Harness Dev.app`。主进程带 `--inspect` 和 `--remote-debugging-port`，`userData` 指向上面的开发目录。
2. Host 是同一个 Electron 可执行文件的另一个进程，环境里有 `ELECTRON_RUN_AS_NODE=1`，参数有 `--expose-internals` 和 Host 调试端口。入口是开发投影里的 `@deepseek-ai/dsh-desktop-host/lib/index.js`。随后的参数是开发 project、`DSH_HOME/profiles/desktop`、primary runtime，以及官方树里的 pnpm 入口和 node-bin。
3. Host 在 stdout 打印 `dsh web: http://127.0.0.1:<系统分配端口>/?token=...`。这次端口是 `50705`。令牌不记在这里。

`profiles/desktop` 里有 `package.json`、`cordis.yml`、`cordis.patch.yml`、`pnpm-workspace.yaml`。`dependencies` 是空的，没有 `node_modules`。

## 主文档

这次没有点欢迎页，也没有进入工作区。主文档地址以调试目标里的 `dsh-app://app/` 为准。
