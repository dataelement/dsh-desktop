# 工作台通知与桌面更新的展示优先级

## 目标与范围

工作台故障和普通新版本提醒不能同时争夺右下角。故障摘要保持紧凑，长诊断通过独立详情面板按需查看。本次仅调整客户端呈现，不改变插件解析、加载链路、用户配置或更新 IPC。

## 规则

- 工作台失败/重启通知通过 `data-dsh-workbench-notice` 标记需要用户关注的已挂载通知；独立详情打开期间也保留标记。
- Desktop preload 仅观察该稳定标记，不依赖翻译文案或压缩类名，不移动 React 管理的节点。观察器只处理变更节点和已有标记集合，不逐次扫描整个会话，并在卸载时释放。
- 自动发现新版本（`available` 且非手动、未打开更新详情）时，如有工作台通知则暂缓展示，不跳过该版本、不丢弃更新状态。最后一个通知关闭后恢复提醒。
- 用户主动检查更新、打开更新详情以及更新失败不受暂缓规则影响。
- 下载中或下载完成等待安装的右下角更新操作优先：工作台浮层临时隐藏，故障状态不清除。此规则不适用于普通 `available`，避免两个通知互相隐藏。
- 工作台详情离开右下角浮层，保留错误来源、阶段、原始原因与恢复操作。关闭详情不代表故障已修复。

## 验收清单

- 同时出现工作台错误和自动新版本时，只出现工作台提示；关闭后新版本仍可显示。
- 从故障摘要打开详情，右下角卡片不增高；详情可以键盘操作、Esc 关闭并恢复焦点。
- 多个工作台错误、长包名和长错误信息不会导致面板溢出；原始诊断仍可查。
- 工作台失败时手动检查更新仍能打开；下载进度及安装入口不被暂缓逻辑吞掉。
- 下载/待安装浮层出现时不与工作台浮层叠放；更新浮层消失后工作台恢复。
- 切换中英文、深浅主题与窄窗口，检查摘要、详情及按钮布局。
- 重复挂载及卸载后无重复观察器或监听器。

DOM 模拟测试不代表已安装 Electron 应用或 Windows 实机布局验证通过。正式发布前仍需对目标平台执行上述真实流程。
