# PPT 转模板能力审查 — 2026-10-09

## 结论与产品边界

当前转换器实现了有界 PPTX → 可编辑 PPTD → PPTX → Office/PDFium 预览链路。它覆盖常见二维页面，需要持续完善高级排版、表格和图表的属性保留。已有回归数量体现已验证行为；完整 OOXML 支持应按下面的能力矩阵验收。

本轮延续现有转换策略。可转换对象进入可编辑模型；具备位置的转换缺口进入可替换占位；样式简化记录诊断；包损坏、资源预算和无效边界进入导入错误。原 PPTX 随模板保留。预览反映转换后的实际导出结果，原稿与转换稿的视觉一致性作为另一项验收。

## 持续验证方式

1. 维护可公开提交的合成样本矩阵：元素类型 × 样式继承 × 组合变换 × 资源状态。每个转换对象核对源数量、位置、层级、内容和诊断。
2. 对每个原生支持能力验证“源 PPTX → PPTD → 可编辑 PPTX”；检查结构属性，再通过固定字体环境的 Office 页图对照。数据正确性、对象遗漏和肉眼可见布局分别设门禁。
3. 对每个降级能力验证“正常相邻对象继续、占位位置正确、页码原因可读、原稿完整、可替换、可保存和复用”。严格 CLI 模式继续要求完整转换。
4. 性能同时记录解析／导出／Office／栅格化阶段、首页与整稿时间，并注明机器、字体、并发负载和原稿页数。完成页图才发布进度。
5. 发布验收追加 macOS/Windows、真实 Host UI、PowerPoint/WPS 编辑保存重开及用户验证。源码测试与这些门禁分别记录。

当前优先后续项：表格样式与富文本；字体／文字排版矩阵；高级图表数据与样式；SmartArt 缓存布局完整性；隐藏、链接和备注语义；存量原稿批量迁移。完整视觉保真应由此矩阵累积证据。

## 大型文件内存门禁

约 81.4 MiB / 57 页实际故障文件完整上传后，原实现 V8 堆约 4 GiB，导致 Harness 退出。导入准备流程现在由 Host 授权并持有库锁、会话归属与审计，在独立 1536 MiB V8 预算进程完成。源文件和素材走本地受控目录，IPC 传递进度和预览结果。进程失败与超时返回导入错误并清理该任务临时资源。

XML 预处理、页面模型和导出按页释放临时树；图形合法性检查采用流式 XML，渲染缓存同时按项数及 512K XML 字符总量控制。超过已有 262144 字符几何预算的路径在创建 DOM 前标记，随后按源边界、变换与层级占位。模板导入页数采用独立 200 页预算；生成 PPT 的配置页数规则继续有效。

本机实际样本完成 57 页高清图、保存和源文件 SHA256 核对。合成样本覆盖小堆内存密集图形、真实子进程内存耗尽及后续导入、处理超时、失败审计和临时资源回收。包内启动与源／构建／ASAR 一致性作为独立门禁。
