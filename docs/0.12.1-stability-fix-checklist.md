## 基线与完成标准

- 当前开发版本：Desktop `0.12.1`，Harness `0.2.1-rc.2`。
- 故障依据：此前 GCP3 只读调查的 `0.12.0` 上报，截止
  `2026-10-19T07:56:54.424Z`。本文未重新统计后续上报。
- 数量表示上报次数和去重安装实例数，不是用户数、失败率；分类之间可能重叠。
- 上游对照：官方 `deepseek-harness` 提交
  `687f282e8625c6b8d11ff58211a90524be2e4317`。
- F01–F06 的代码修复和本机回归已完成，下面按项目记录状态。Windows 最终安装升级、
  macOS x64 和线上验证仍待完成；当前结果不能替代这些发版验收。

## 发版前必须完成

尚不能证明所有实例都由开关操作触发。

- [x] 关闭 DeepSeek 图片输入时，同次更新删除 `imagePixelBudget`、`imageMaxBytes`，保留其他模型字段。
- [x] 为已经保存的矛盾配置提供可恢复路径；涉及改写时保留原配置，只处理明确识别的冲突字段。
- [x] 补控件行为回归：关闭、重新开启、其他模型字段保留；覆盖保存及重启加载，不能仅检查补丁字符串。

代码入口：`patches/@deepseek-ai+dsh-client-ui-settings-models+0.2.1-rc.2.patch`。
回归入口：`test/model-settings-render.test.mjs`、`test/model-picker-patch.test.ts`。
上游 `ModelInputTypes.tsx` 已有清理逻辑及专门测试，我们的定制控件绕过了它。

验收：带图片限制的模型关闭视觉并保存后，重启不再出现
`text-only catalog model ... cannot declare image request limits`；旧异常配置可恢复且无关字段不丢失。

### F02 splash 加载、窗口销毁与退出竞态

状态：已加入生命周期保护和原生恢复。线上存在 `loadFile -> loadDesktopResource -> showSplash`
的窗口销毁错误调用栈。splash 错误共 22 次 / 13 个安装实例，不能全部归因于该竞态。

- [x] 修正 `loadURL` 失败后无条件 `loadFile` 的路径，保留第一次失败的原始 cause。
- [x] 在失败及后续导航入口检查退出/重启、窗口销毁、导航已失效状态。
- [x] 区分 `ERR_ABORTED` 与真正的加载失败，避免预期导航取消触发恢复重载。
- [x] 渲染进程不可用时提供原生恢复入口，避免恢复操作本身依赖同一个失效 renderer。
- [x] 补失败后窗口销毁、GPU 降级重启、连续导航、正常关闭、真实文件加载失败回归。

代码入口：`src/main/index.ts` 的 `loadDesktopResource`、`showSplash`、
`installMainWindowRendererRecovery`；同时检查该资源加载函数的恢复页调用者。
回归入口：`test/main-window-recovery.test.ts`、`test/gpu-fallback.test.ts`。

验收：退出或重启途中不会再次加载旧窗口；真实加载失败保留原始诊断且原生恢复可操作。
此项不等于解决 Windows 首次创建 renderer 失败，后者见 F07。

### F03 错误模型地址导致启动失败且无法修改

状态：已加入 UI 和持久化边界校验及原生恢复。`Invalid URL` 对应启动上报 30 次 / 10 个安装实例；样本包含内置 DeepSeek
适配器在普通 Profile 和 Safe Mode 中失败。上游运行时仍可能抛出此错误。

- [x] 核对新建和编辑提供方的地址校验，并在实际配置写入边界校验；覆盖缺少协议、空白及非法地址。
- [x] 区分显式配置地址和环境变量来源，诊断中标明来源，不记录密钥或敏感完整配置。
- [x] 启动因内置模型配置失败时，允许通过不依赖 Harness 成功启动的入口修正配置。
- [x] 用临时 Profile 覆盖非法地址启动、修正、重启成功的完整流程。

代码入口：模型设置补丁、`src/main/` 的启动失败及恢复入口。
回归入口：`test/plugin-startup-failure.test.ts`、`test/safe-mode-runtime.test.ts`，
另补地址保存校验的行为覆盖。

验收：用户不会因一个错误地址被永久挡在设置界面之外；核心配置错误不会被误归因于第三方插件。

### F04 workspace 与凭据异常保持与上游一致

状态：保持与上游运行时一致，避免 Desktop 宿主进程侵入。workspace 与凭据由 `@deepseek-ai/dsh-workspace` 和
`@deepseek-ai/dsh-credentials-local` 自行管理其数据生命周期与迁移，Desktop 不在启动前越权做静态拦截与阻断。

- [x] 移除 Desktop 宿主对 `workspace.json` 的全量 Zod 静态审查门禁，避免因上游结构迭代或扩展字段导致启动误阻断。
- [x] 移除 Desktop 宿主对 `.credentials.yaml` 的强行格式拦截，沿用上游凭据库原生的迁移与加载逻辑。
- [x] 启动恢复集中于真正属于 Desktop 组合范围内的 YAML 补丁、Cordis 编排与模型端点自愈。

代码入口：`src/main/state/startup-config-recovery.ts`。
回归入口：`test/startup-config-recovery.test.ts`、`test/startup-config-runtime.test.ts`。

验收：workspace 与凭据的读写和校验行为与上游官方一致，不增加外部阻断风险。

### F08 Harness 非预期退出 0 与 OOM

- [ ] 为每次启动分配可关联的运行标识，区分主动停止、更新交接、启动失败清理和非预期退出。
- [ ] 保留首个 fatal、退出前 stderr、shutdown 请求/确认和可获得的内存信息，避免最后一行普通日志被误当根因。

验收：退出码 0 不再是唯一诊断信息，OOM 能定位进程及阶段；尚无复现证据时不得声称已根治。

  另有行为单测；尚未在受影响 Windows 机器验证原生恢复对话框。

  Harness 子进程、认证 HTML、bootstrap 执行注册、node-pty 实际执行、语音原生模块、
  PPT 模块及 Office DOCX/PPTX/XLSX 生成重读与 PDF 转换。
- 使用 tabbit 在打包后的 Harness 上确认实际 UI 挂载、无 `pageerror`；非法地址提示并禁用
  Apply，有效地址和关闭视觉输入保存后刷新仍保留，截图已检查。浏览器和临时子进程已关闭。
- Windows signed-installer smoke 已接入上述运行时探针，覆盖两个安装目录；本机没有执行
  Windows、签名安装/旧版升级或 macOS x64。未改动已安装应用及真实用户 Profile，未发布。

新增回归：`desktop-navigation.test.ts`、`startup-config-recovery.test.ts`、
`startup-config-runtime.test.ts`、`model-endpoint-settings.test.mjs`、
`packaged-dependency-closure.test.ts`。扩展了 `model-settings-render.test.mjs`、
`plugin-startup-failure.test.ts`、`harness-node-entry.test.ts` 和 `verify-asar-unpack.test.ts`。
loader 测试的契约调整是：本地包显式拒绝的 `exports` 子路径必须继续失败，
不能拼接宿主版本；真正缺失的 `@deepseek-ai/*` peer 仍可从安装目录 fallback。

恢复边界：

- main 在后端加载前检查默认 workspace/credentials 路径、旧 `settings.yaml`、全局 patch
  和当前 web/Safe Mode Profile patch。使用安装版本的 workspace schema 和凭据解析器。
  自定义存储路径和动态 `!!js` 配置仍由 Harness 判断；不会执行表达式或泛扫第三方私有数据。
- 配置恢复等待当前启动及 Profile 回滚结束，配置修复先停止 runtime，持文件锁复核内容，
  创建独立 `0600` 原文件备份，再原子替换；
  拒绝越界路径、symlink 和并发修改。未知损坏需定位原文件或导入有效修正文件，不自动清空。
- DeepSeek 显式 baseURL 可备份后移除，回到启动环境/官方默认地址。自定义 pi-ai 地址需
  导入修正文件；环境变量需在其来源修改并重启。rc.2 禁止 `.env` 设置 `DEEPSEEK_BASE_URL`，
  此时定位来源并提示移除。凭据库中的同名 ref 不参与 baseURL 选择。
- 旧 workflow 预设按所有者停用并保留实现原文；修正接口后可导入恢复，未经修正的旧引用
  仍会被提示。第三方包内部引用沿用结构化根插件归属，不能当作宿主缺包自动补装。
- 完整性 SHA256 检查只在签名前 afterPack 运行；签名后的 Windows smoke 验证签名与实际
  运行，不用签名前的二进制 hash 判断已签名文件。
