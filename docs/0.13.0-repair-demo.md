# 0.13.0 本地维修场景演示

仅供开发客户端，必须同时满足：非打包应用、显式设置 `DSH_DEV_REPAIR_DEMO=1`、专用 Desktop Profile 名称包含 `repair-demo`、Harness home 路径包含该名称。正常用户 Profile 不开放菜单。演示不会连接市场下载或替换应用版本。

## 操作入口

在开发客户端的「维修场景演示」菜单依次体验：

1. **模拟插件阻断启动**：在专用 Harness Profile 安装本地 `dsh-demo-startup-failure` 插件，重启后其 `apply` 抛出明确带 `[DEMO]` 的错误，走真实加载与恢复页面。第一轮「一键修复」模拟将插件从 1.0.0 升到 2.0.0，故意保留错误；重启后第二轮停用该插件以恢复。
2. **预览未知启动错误**：使用模拟错误证据打开恢复页，不表示刚发生了真实崩溃。该页应仅开放安全模式维修 Agent。
3. **清除演示故障并正常重启**：只可逆停用本演示插件，保留插件代码、会话、配置及其他内容。
4. **正常环境维修 Agent**：走正常客户端的维修会话入口。
5. **安全模式维修 Agent**：走安全模式维修入口，需观察安全模式状态提示及预置维修模式。

一键修复的升级候选明确标为「本地模拟升级（非市场下载）」。不使用真正的应用版本回退，以免替换开发客户端。实际安装包回退仍需单独在对应平台验收。

## 数据保护与限制

所有已存在的待写文件先用唯一 `.repair-demo-backup-*` 文件备份，再原子替换；拒绝软链接路径与非演示所有权的同名插件。再次开启第一种场景时，只清除涉及该演示插件的未验证维修轮次，以便重复演示；其他维修记录保留。前三种场景不发送模型请求；选择维修 Agent 只打开修复模式并预填短草稿；仅当用户点击发送后才提交模型请求。实际回复取决于模型配置、权限及额度。

## 验证

`npx vitest run test/development-repair-demo.test.ts` 覆盖显式开关、专用目录护栏、真实插件 apply 抛错、本地模拟升级、停用与重新启用、保留无关维修记录、拒绝同名用户包与软链接、三类入口路由。该测试不启动 Electron；客户端与 Harness 实际显示需另行观察。

## 本次本机演示

启动命令（仓库根目录）：

```bash
DSH_DEV_REPAIR_DEMO=1 DSH_DEV_PROFILE=dsh-desktop-dev-v013-repair-demo DSH_DEV_HARNESS_PORT=43260 DSH_DEV_MOBILE_PORT=43261 ./node_modules/.bin/electron .
```

实际观察到演示插件阻断启动 → 第一轮本地升级 → 第二轮停用 → 正常界面恢复；插件文件保留、disabled 开关生效。未知错误预览仅提供安全模式维修 Agent。正常/安全两种维修会话均实际选中了修复模式；当前账号模型请求被服务商以 403／insufficient_user_quota 拒绝，因此尚未演示模型实际回复和维修执行。

类型检查、构建及 35 项相关测试通过。新增演示护栏测试 4 项通过。本轮全量回归 2241 项通过、3 项失败：已有 PPT 字体渲染失败，另有 generation-build-approval 及 Office 重算测试失败；Office 重算与 generation-build-approval 单独复跑均通过；全量结果仍记录为该轮实际结果，不混称全量通过。

## 应用版本回退交互演示

开发菜单新增「模拟应用版本回退成功」与「模拟应用版本回退失败」。两者均先恢复 owned 演示插件的启动阻断，使已知故障页显示 `回退应用至 0.12.0（模拟）`。此目标只用于演示，不是当前客户端实际安装历史。

共用流程为确认（可取消）→处理中→结果。成功场景可逆停用 owned 演示插件，实际启动普通 Harness，核心服务 ready 后展示「模拟回退成功」；用户点击「继续使用」后打开普通界面。失败场景返回明确标注模拟失败的恢复选择页，用户点击「让 Agent 帮我修」后才进入安全模式。两者不调用真实 updater，不下载或替换应用，也不修改真实回退账本。

真实应用回退仍由安装历史、归档、平台和数据兼容性资格限制控制。本演示不代表 macOS/Windows 安装包降级或用户数据跨版本兼容已验收。确认页、进度页和结果页使用同一新页面；窗口关闭会释放流程等待，避免阻塞后续重开。页面支持显式浅色、深色及跟随系统设置。
