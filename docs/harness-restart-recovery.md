# Harness 重启循环：诊断与修复边界

## 状态必须区分

- **待重启生效**：已提交的新 generation 与运行/投影状态不同，可以正常停止 Host 后重新投影。
- **安装状态异常**：已登记 generation 的 Profile 入口被真实目录或外部链接替换。运行中不得覆盖它，也不能把它包装成重启即可修复。应先停止外部更新来源，保留冲突目录备份，再通过宿主管理的重装、移除或离线投影恢复。
- **工作台注册或操作失败**：保留包名、阶段和原始原因；身份冲突和迁移授权失败不是待重启状态。
- **连接或停止失败**：区分 Host 存活、进程退出、管道关闭与前端重连；不以刷新页面替代进程恢复。

## 数据与权限

市场授权决定可自动迁移的身份，不因包名相同就把一个仓库的数据转给另一个仓库。无会话、笔记等数据的旧入口可以由用户显式清理；存在数据时保留旧归属与恢复材料。不得为修复循环而放宽迁移接口授权。

托管 generation 保持不可变。第三方插件自身的更新器不能被假定识别 Desktop 私有协议；Desktop 只能诊断并阻止不安全的运行期覆盖，不能声称已阻止所有外部进程写文件。兼容性应通过第三方插件遵守宿主更新通道解决，而不是默认修改用户全局配置或禁用所有插件自动更新。

## Host 停止

Host 进程的 `exit` 表示旧 Host 已结束。`close` 还要等待标准输入输出管道关闭；第三方插件的后代进程可能继承这些管道。停止等待以 `exit` 为准，保留原有优雅退出确认和 TERM/KILL 升级期限；启动失败的 `error` 也必须结束等待。不因为管道仍被其他进程持有，就报告旧 Host 在 SIGKILL 后仍未退出。

## 验证与交付

1. 临时 Profile 复现身份冲突、市场授权和有数据/无数据旧入口场景。
2. 临时插件入口复现托管链接被真实目录或外部链接替换，断言诊断准确且运行期不改该入口。
3. 真实 Host 子进程产生持有 stdout/stderr 的后代，验证 Host 已退出后停止不误超时。
4. 在隔离开发 Profile 验证实际页面的错误、待重启和异常安装状态，不触碰真实用户 Profile。
5. 构建、测试通过不等于正式包验收；macOS/Windows 安装包的重启、junction/占用文件和重连流程仍需各平台实测。
