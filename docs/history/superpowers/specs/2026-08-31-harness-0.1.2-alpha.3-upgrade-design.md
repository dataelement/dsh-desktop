## 已确认的上游结构性变更（alpha.1 → alpha.3）

### 删除的包

| 上游包 | dsh-desktop 现状 | 处置 |
| --- | --- | --- |
| `@deepseek-ai/dsh-session-persistence-sqlite` | 未直接依赖；在 `test/release.test.ts` 的 `excludedHarnessPackages` 里 | 包已从上游消失，排除项自然继续成立。清理该行（连同复核 `dsh-storage-sqlite` 是否仍需列出）。**不影响桌面端会话可见性**——桌面端一直用 JSONL 权威存储，SQLite 仅曾作为可选后端，从未打包。 |
| `@deepseek-ai/dsh-agent-spine-demo`（`packages/examples` 整组删除） | `package.json:60` 直接依赖，代码中无其他引用 | 上游把其配置行内联进 `dsh-sdk-minimal`。移除该依赖行；复核它是否在 `@deepseek-ai/dsh` 运行时闭包 / `patches/@deepseek-ai+dsh` 里，若在则同步移除。 |

### 新增的包

`packages/client/ui-schedule`、`packages/util/deque`、`packages/util/time`、
`packages/util/values`。实施阶段按 `@deepseek-ai/dsh` 与 `dsh-web-app` 的依赖闭包
判断哪些需要进 `package.json` 和 dsh 闭包补丁（参照 alpha.1 的
`test/desktop-plugin-closure.test.ts` 不变量）。

### 会话持久化（alpha.3 breaking change，但对桌面端近乎零影响）

上游 `refactor(session)!: remove SQLite persistence backend`：
- 删除的是**权威存储后端** `session-persistence-sqlite`（JSONL 的可选替代品）。
- 保留 `session-query-sqlite`（可丢弃的 FTS5 搜索索引，从 JSONL 重建）与
  `dsh-storage-sqlite`（通用 domain-KV）。
- 桌面端 profile 用 `dsh-session-persistence-jsonl` 作为唯一权威存储，历史会话
  全部照常可见，无需迁移或导出。
- 「请用旧版本导出」仅针对手动把后端配成 sqlite 的上游 CLI 用户，与桌面端无关。

## 实施步骤

### 1. 本地打包桥接

在 `/Users/alex/Documents/Code/AI/deepseek-harness`：

```bash
git checkout dsh-v0.1.2-alpha.3
corepack pnpm install --frozen-lockfile
corepack pnpm run build:official
corepack pnpm exec tsx scripts/release/pack.ts --family vendor --out dist/npm-vendor --concurrency 8
corepack pnpm exec tsx scripts/release/pack.ts --family dsh    --out dist/npm-dsh    --concurrency 8
```

产物复制进新目录 `packages/harness-0.1.2-alpha.3/{npm-vendor,npm-dsh}/`，
附一份 `README.md` 说明来源与命令（照抄 alpha.1 的结构）。
删除 `packages/harness-0.1.2-alpha.1/`。

> vendor tarball（cordis / cosmokit / schemastery 等）若版本号未变，仍要重新打包并更新路径。

### 2. 依赖切换

- `package.json` 中所有 `harness-0.1.2-alpha.1/...-0.1.2-alpha.1.tgz`
  → `harness-0.1.2-alpha.3/...-0.1.2-alpha.3.tgz`（含 vendor 段实际版本号）。
- 删除 `@deepseek-ai/dsh-agent-spine-demo` 行。
- 按闭包结论补入需要的新增 `util/*` 包。
- `packages/dsh-desktop-market-installer` peer 范围 → `^0.1.2-alpha.3`。
- 重新生成 `package-lock.json`（`npm install`，来源为本地 tarball）。

### 3. Patch 适配（16 个）

逐个把 `patches/*+0.1.2-alpha.1.patch` 重建到 alpha.3 构建产物并改名为
`+0.1.2-alpha.3.patch`。对每个补丁判定：

- **仅行号 / CSS hash 偏移**：重新生成 diff。
- **上游 API 改名 / 结构变更**：跟随调整（参照 alpha.1 记录的 `ctx.uiWorkspace`、
  `submitLabelKey*`、`useSessionPendingInteraction` 等模式，alpha.3 可能再动）。
- **上游已原生提供**：删补丁，在升级文档记录「交还上游」。
- `@deepseek-ai+dsh` 闭包补丁：同步 spine-demo 移除、util 新增包的 manifest 注入，
  更新行号。
- `dsh-api-session-controller` 补丁：复核会话分页 / 模型目录接口在 alpha.3 是否再变。

产出新的补丁清单表（新增 / 删除 / 仅偏移三类）写进升级文档。

### 4. 宿主侧脚本与桌面插件

- `scripts/release/install-brand-assets.mjs`：复核对 alpha.3 `dsh-web-frontend` 前端资源的

## 风险

- **上游构建耗时 / 依赖体积大**：`pnpm install` + `build:official` 可能较慢，磁盘占用高。
- **alpha.2 中间态被跳过**：若某改名分两步完成，直接 diff 可能漏掉过渡说明；以最终
  构建产物为准，diff 仅作线索。
- **补丁漂移**：CSS module hash 每次构建都可能变，需以 alpha.3 实际产物为准逐一重取。
- **闭包不变量**：新增 `util/*` 包若进了 `@deepseek-ai/dsh` 闭包却漏注入 manifest，
  会整棵插件树失败（alpha.1 已踩过）。
