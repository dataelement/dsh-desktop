## 上游结构性变更（alpha.3 → alpha.4）

### 会话破坏性变更（本次最需关注）

`refactor(session)!: distinguish event seqs from log offsets`（commit `27bf103`）：
`@deepseek-ai/dsh-brand` 新增 `BrandedNumber<B>` / `brandNumber()`；`dsh-session` 拥有
`SessionSeq`（指已存在事件）与 `SessionLogOffset`（指日志间隙/前缀长度/读取偏移）两个 brand，
`SessionSeqCursor = SessionSeq | -1`、`OptionalSessionSeq = SessionSeq | null`。
`SessionHeader.seedLength` 被 `isSeeded: boolean` + 旁路 `inheritedEventCount` 取代。

**关键：这是编译期 TS branding 重构。**上游 Agent Note 明确：
> API、SDK、DeepSeek、telemetry、query row 与 JSON 表示继续携带普通 number；
> 磁盘 v0 格式与公共数值 wire 不变。

因此移动端桥接走的 HTTP `/api/session/page`（`throughSeq` 为普通 number）与 v0 JSONL
理论上不受影响。但 `dsh-api-session-controller` 的 `lib/index.js` 内部代码形状会变
（补丁 context 行漂移），且 `test/session-create-remote-event-patch.test.ts` 需复核。
**验证阶段以实机分页 + 桥接冒烟为准，不只靠单测。**

### 被删除 / 移动的包

| 上游变更 | dsh-desktop 现状 | 处置 |
| --- | --- | --- |
| `@deepseek-ai/dsh-tool-subagent-report` 删除 | 在 `test/release.test.ts` `excludedHarnessPackages` | 排除断言变 vacuous —— 清理该行 + 复核是否仍为传递依赖 |
| `code-runtime-python` 从 `packages/code-runtime/` 移到 `packages/experimental/` | 已排除，包名 `@deepseek-ai/dsh-code-runtime-python` 未变 | 无影响，仅确认 tarball 名不变 |

包总数 257 → 256（净 −1）。**无 dsh-desktop 需要新增的包。**

### ui-* 包普遍重构

`ui-workspace` / `ui-trajectory` / `ui-settings-models` / `ui-model-selection` /
`ui-agent-preset` / `ui-chat` 全部重新构建（`147 files changed` in patch-relevant packages）。
CSS module hash 会再次变化；bundle 结构可能漂移。ui-trajectory / ui-workspace 还删除了
`src/invariant.ts`（内部清理，不影响补丁意图）。

## 实施步骤

与 alpha.3 升级同形状，但结构性改动更小。

### 1. 本地打包
`git checkout dsh-v0.1.2-alpha.4` → `corepack pnpm install --frozen-lockfile` →
`build:official` → `pack.ts --family vendor|dsh`。产物进新目录
`packages/harness-0.1.2-alpha.4/{npm-vendor,npm-dsh}/` + README。删除
`packages/harness-0.1.2-alpha.3/`。

### 2. 依赖切换
`package.json` 所有 `harness-0.1.2-alpha.3/...-0.1.2-alpha.3.tgz` →
`harness-0.1.2-alpha.4/...-0.1.2-alpha.4.tgz`（含 vendor 段实际版本号，逐一核对 tarball 文件名）。
3 个桌面插件包（client-ui / preset-transfer / market-installer）的 `@deepseek-ai/dsh*` peer
`^0.1.2-alpha.3` → `^0.1.2-alpha.4`。重生成 `package-lock.json`（`npm install`），
验证 lockfile 无 `harness-0.1.2-alpha.3` 残留、无 registry-resolved `@deepseek-ai/dsh-*`。

### 3. 补丁适配（16 个）
逐个 `git mv +0.1.2-alpha.3.patch → +0.1.2-alpha.4.patch`（cordis-plugin-loader 跟随其
vendor 版本号），对着 alpha.4 构建产物重建：
- **闭包补丁 `@deepseek-ai+dsh`**：注入的 4 个 `dsh-desktop-*` 行不变，仅 manifest 行号 /
  blob-index 更新；确认 alpha.4 未从 dsh 依赖里删/加影响闭包的包。
- **8 个机械补丁**（cordis-plugin-loader / dsh-client-modules / ui-deliverables /
  ui-directory-picker-native / ui-layout / ui-sidebar / llm-deepseek / llm-pi-ai）：
  多为改名 + 行号偏移；directory-picker / sidebar / layout 复核补丁目标代码仍存在。
- **provider 错误组 3 个**（dsh-api-session-controller / ui-chat / ui-trajectory）：
  ui-trajectory 有较大重构（`TrajectoryView.tsx` +69 行、`views.client.spec.tsx` +178），
  需重点复核 provider 错误提示的注入点是否还在、是否被上游原生化。
  dsh-api-session-controller 受会话 branding 重构影响，`summaryFor` / `api-session/added`
  区域 context 行会漂移。
- **CSS-hash 组 4 个**（ui-model-selection / ui-workspace / ui-settings-models /
  ui-agent-preset）：alpha.4 重建 → 每个 hash 再次迁移。ui-workspace 的
  `Rows.module.css` + `WorkspaceBrowser.module.css` 都有 diff，unread 补丁的 base 串要重取。
去留判定标准不变，任何「上游已原生」的能力删补丁并记录。

### 4. sqlite/subagent-report 排除项
`test/release.test.ts`：`dsh-tool-subagent-report` 排除行随上游删包处理（删除或加注释）；
复核 `dsh-session-persistence-sqlite`（alpha.3 已删的注释）与 `dsh-storage-sqlite`。

### 5. 宿主脚本 / 主进程 / 移动端桥接（重点）

## 风险
- **会话 branding 重构泄漏到 wire**：Agent Note 说不会，但 `dsh-api-session-controller`
  补丁与移动端分页要以实测为准。
- **ui-trajectory / ui-workspace 大改**：补丁可能需要实质 rebase 而非机械 hash swap，
  甚至部分能力被上游原生化。
- 补丁上下文含构建机绝对路径的 4 个 CSS 补丁（alpha.3 已记录）——换机器重打包仍需重生成。
- 子代理易误入主检出（alpha.3 踩过两次）——每个实施 brief 必须强化「只在 worktree 内操作」。
