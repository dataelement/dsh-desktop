<p align="center"><strong>Помимо официальных моделей DeepSeek, DSH Desktop поддерживает популярные сторонние поставщики моделей. Вскоре появятся и другие настольные возможности на базе DSH.</strong></p>

DSH Desktop упаковывает локальный веб-интерфейс DeepSeek Harness в настольное приложение. Оно автоматически запускает локальный экземпляр Harness, управляет случайным loopback-портом, сохраняет Profile, плагины и сессии, а после готовности Harness сразу открывает полный интерфейс. Рабочие пространства проектов добавляются и управляются непосредственно в интерфейсе Harness.

> [!IMPORTANT]
> DSH Desktop пока находится на стадии ранней предварительной версии и зависит от быстро развивающегося `@deepseek-ai/dsh@0.1.1-rc.1`. Выпуски для macOS подписаны кодовой подписью и нотариально заверены Apple; актуальные установщики распространяются через официальный сайт.

## Загрузка

Загрузите DSH Desktop для macOS и Windows с [официального сайта](https://www.dshdesktop.com/#download).

Установленные версии для macOS и Windows автоматически проверяют обновления после запуска и затем каждые шесть часов. Обновления загружаются в фоновом режиме, а после завершения приложение предлагает перезапуск. Проверку также можно запустить вручную, выбрав **Check for Updates…** в меню приложения.

## Зачем существует этот проект

DeepSeek Harness уже предоставляет полноценную среду выполнения Agent и Web UI. DSH Desktop не реализует Harness заново, а добавляет возможности хоста, необходимые настольному продукту:

- Работа без ручного запуска CLI и управления локальными портами
- Автоматическое создание принадлежащего приложению каталога запуска Harness при старте
- Добавление и управление рабочими пространствами проектов через встроенный в Harness выбор каталогов
- Единое управление дочерним процессом Harness, проверками готовности, журналами и завершением работы
- Хранение Profile, плагинов и сессий вне каталога установки приложения, чтобы обновления не удаляли пользовательские данные
- Точки входа для сборки пакетов macOS и Windows

## Возможности

- Прямое открытие Harness без дополнительной стартовой страницы
- Запуск без первоначального выбора каталога за счёт создания и повторного использования внутреннего каталога запуска
- Повторная попытка, просмотр журнала и выход при сбое запуска Harness
- Команды меню Harness для перезапуска дочернего процесса и просмотра его журнала
- Корректное завершение дочернего процесса Harness при выходе из настольного приложения
- Прослушивание только случайного порта `127.0.0.1` при каждом запуске
- Удаление привилегий Node.js из Renderer и включение `contextIsolation`, sandbox и ограничений навигации
- Единый логотип бренда DSH в окне приложения и боковой панели Harness
- Импорт и экспорт полных пользовательских Agent Preset в виде переносимых [пакетов `.dshpreset`](docs/preset-packages.md) с проверкой конфликтов и предупреждением о доверии перед установкой
- Готовая иконка приложения DSH в форматах macOS ICNS и Windows ICO

## Быстрый старт

### Требования

- Node.js 22 или новее
- npm
- macOS на Apple Silicon или Intel либо Windows x64

### Локальная разработка

```bash
git clone https://github.com/dataelement/dsh-desktop.git
cd dsh-desktop
npm install
npm run dev
```

Команда `npm install` запускает `patch-package`, чтобы повторно применить настройку поставщиков моделей, перенос пакетов Preset и оформление боковой панели DSH Desktop, затем устанавливает брендовые ресурсы и среду выполнения Electron.

### Проверки качества

```bash
npm test
npm run typecheck
npm run build
```

### Упаковка

```bash
# Создать неподписанные DMG- и ZIP-артефакты для текущей архитектуры Mac
npm run package:mac

# Выполнять каждую команду на Mac или CI Runner соответствующей архитектуры
npm run package:mac:arm64
npm run package:mac:x64

# Создать NSIS- и Portable-артефакты на машине или Runner с Windows x64
npm run package:win
```

Harness содержит нативные модули, зависящие от архитектуры. Для macOS ARM64, macOS Intel и Windows x64 зависимости необходимо переустановить и собрать на соответствующей платформе. Специализированные скрипты перед упаковкой проверяют текущие `platform/arch`, чтобы не создавать артефакты, которые выглядят успешно собранными, но не содержат нативных зависимостей.

## Архитектура среды выполнения

```text
DSH Desktop (Electron Main)
├── Каталог запуска, принадлежащий приложению
├── Жизненный цикл дочернего процесса Harness
├── Случайный loopback-порт и проверки готовности
├── Нативное журналирование и действия восстановления
└── Защищённый BrowserWindow
     └── http://127.0.0.1:<random>  DeepSeek Harness Web UI

Electron userData
├── launch-root/
├── logs/harness.log
└── harness/
    ├── profiles/
    ├── sessions/
    └── Плагины и пользовательские данные
```

Harness работает в отдельном дочернем процессе Electron Node. Разрешение `--expose-internals`, необходимое Cordis HMR, предоставляется только этому дочернему процессу и никогда — Web Renderer.

## Структура проекта

```text
src/main/             Главный процесс Electron, окна и жизненный цикл Harness
src/shared/           Общие типы среды выполнения
patches/              Воспроизводимые настройки UI для закреплённой версии DSH
scripts/              Установка брендовых ресурсов и проверки упаковки для целевых платформ
test/                 Тесты настроек, среды выполнения, безопасности и поставщиков
build/                Ресурсы иконок приложения
```

## Текущее состояние проверки

- macOS Apple Silicon: проверены процесс разработки, реальный запуск Harness, упаковка DMG, подпись кода, нотариальное заверение Apple и смонтированный артефакт
- macOS Intel: конфигурация упаковки и проверки платформы готовы; для проверки выполнения всё ещё нужен Intel Mac или Runner
- Windows x64: конфигурация NSIS/Portable и проверки платформы готовы; для проверки выполнения всё ещё нужен Windows Runner
- Windows ARM64: пока не поддерживается
- Автоматические обновления: пока не интегрированы

## Версия upstream и патчи

Проект сейчас закрепляет `@deepseek-ai/dsh@0.1.1-rc.1`. Начальный список поставщиков и настольный интерфейс переноса Preset фиксируются с помощью [`patch-package`](https://github.com/ds300/patch-package) в каталоге [`patches/`](patches/), а не зависят от неотслеживаемых изменений в `node_modules`.

При обновлении DSH:

1. Проверьте контракты upstream для Settings, Credentials и Provider Directory.
2. Повторно примените или перепишите изменённый интерфейс первоначальной настройки.
3. Создайте патч заново.
4. Проведите регрессионные проверки с реальным запуском Harness и процессом настройки поставщика.
